# Wake 架构审查

只将会留下长期架构约束的 Wake 工作纳入架构流程；显式调用本 Skill 的普通任务仍按普通任务处理。

## 证据边界

- 当前实现以源码、清单、测试和实际产物为证据。
- 已实施约束以状态为 `accepted` 的 ADR 和 `engineering/architecture-boundaries.json` 为依据；`proposed`
  只表示候选决策，不能作为当前边界或机器策略的权威。
- `engineering/README.md` 和其他叙述文档用于导航和解释；引用其结论前须与当前实现、清单和门禁核对。
- 当前实现、机器策略和有效 ADR 不一致时，明确报告差异，不静默选择其中一方。

## 决策路由

1. 若请求和最小实现证据表明现有所有权、依赖、数据流、身份、并发模型、发布事务和契约均不变，
   只按普通任务处理，不进入 ADR 流程。
2. 其余任务先读 `engineering/decisions/README.md`，从验证索引定位相关 ADR，并沿其直接
   `Supersedes`、`Superseded by`、`Amends` 与 `Amended by` 关系确认当前决策。仅当索引、命中 ADR
   和目标路径仍不足以定位受影响能力、源码、测试或维护文档时，再读取 `engineering/README.md` 的相关片段。
3. 若任务可能改变本 Skill 描述中的长期边界，或用户要求审查、整理 decisions，先读取
   [adr-workflow.md](references/adr-workflow.md)，再判断是沿用、新建、部分修订还是完整替代决策。
4. 若仅实现已有 `accepted` ADR 且不改变其决策或不变量，引用该 ADR，不重复创建决策。

## 工作纪律

- 先搜索定位，再只读取命中的索引条目、直接 ADR 关系、相关源码和测试片段；仅在证据冲突、关键问题
  未决或测试失败时扩大范围。复用未变化的证据，决策与验证路径充分后停止探索。
- 每个判断选取最接近的当前事实源：行为看实现与聚焦测试，依赖看清单，机器边界看策略，验证命令看
  最近的清单、脚本或 ADR `Validation`。除非这些证据冲突，不为重复确认同时读取工程总览、TESTING、
  CI 和根清单。
- 静态搜索足以覆盖调用关系时，不为证明“未受影响”扩读未命中的调用方。公共、跨进程或持久化契约
  涉及生成代码、动态注册、配置驱动消费者或历史产物时，搜索未命中不能单独证明安全；须检查对应的
  生成或注册入口、协议两端、旧格式和兼容测试，再按证据收敛。
- 普通局部行为任务若目标源码与所属清单已足以确定实现、测试和门禁，不再读取根清单；仅当需要解析
  workspace 继承字段或无法确定命令时读取命中的根清单片段。
- 只读审查以相关不变量各有直接实现证据及最近的测试或机器门禁证据为充分，不穷尽全部调用方和测试
  矩阵。仅当请求涉及历史、计划或成熟度时读取 AUDIT、PLAN 或 ROADMAP。
- 在源头收窄工具输出；进度与最终报告只保留结论、契约变化、已运行或跳过的验证和剩余风险，不粘贴
  长原文或完整日志。只把彼此独立、有明确交付物且不能由一次定向搜索完成的任务交给代理，并只传递
  必要上下文。
- 改变可执行行为、公共或跨层契约、缓存、持久化、跨进程、机器边界、validator、构建脚本或 CI 策略
  代码时，先新增或调整表达目标不变量的最小测试或 fixture，并运行确认它因预期缺口失败；然后才写最小
  实现，先让聚焦测试转绿，再运行与风险匹配的门禁。
- 已有精确失败测试时先复现，不重复造测试。行为保持重构先运行现有聚焦测试作为基线，仅在覆盖缺口
  存在时补测试。
- 只读审查、计划、test-only 变更，以及纯 ADR、文档、UI 元数据、格式或版本同步不制造虚假失败。行为
  缺陷无法稳定复现时先构造最小 repro；仍不能复现则在修改实现前报告阻塞。
- 节制上下文不得成为跳过必要证据、测试或验证的理由。

## 变更原则

- 兼容与迁移依据用户目标、现有公开承诺、版本策略和有效 ADR 决定；不得默认采用破坏性切换。
- 形成最小完整变更：只同步实际受影响的实现、调用方、类型、诊断、测试、文档或发布配置。
- 旧路径仅在其替代方案已验证、删除属于当前范围且不违反兼容承诺时移除。
- 不在 Skill 中复制领域所有权、测试矩阵或命令；这些内容从当前工程文档、清单和 CI 获取。

## 验证

优先从目标最近的测试入口和所属 package/Cargo 清单选择门禁；仅当变更触及跨项目门禁、命令不明或
聚焦验证失败时读取 `engineering/TESTING.md` 或 CI。普通局部任务在聚焦测试和所属 crate/package 门禁
通过后停止，不默认升级到全 workspace 或发布矩阵。ADR 或机器边界变化时还须运行当前仓库定义的架构
测试与架构检查。只读审查不默认运行全量门禁；索引、直接关系、目标策略或实现及最近的验证证据足以
回答时停止，仅在结论依赖当前执行结果、证据冲突或用户明确要求时运行最小相关检查。完成时报告已验证
证据、未运行项目及剩余风险。

修改或整体审查本 Skill 时才读取 [behavior-evals.json](references/behavior-evals.json)。每例使用独立新代理；
`mutation: forbidden` 必须由宿主强制只读，`mutation: allowed` 必须使用干净、可丢弃的独立工作区。无法提供
对应隔离时跳过该例并标为 unsupported，禁止在用户工作树中模拟。只传递原始请求并在完成前隐藏预期；
按可观察的 Skill 选择证据、读取、写入、命令和行动顺序评分，不匹配回答措辞。宿主不提供选择事件时将
该项标为 unsupported，不以代理自报代替。触发变化运行全部隐式正反例；工作流变化运行受影响场景和一个
负向对照；仅在整体审查或证据冲突时运行全套场景。
