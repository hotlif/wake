### [B1] `high` · docs/TS-SYNTAX-SUPPORT.md 支持矩阵复核

**声明**：§2「enum E { ... }（值语义 → IIFE）✅ ts_value.rs:parse_enum()」——无任何 caveat

**实测**：

```
enum 成员用裸名引用同一 enum 的前序成员时，wake 直接原样发射该裸标识符，未改写为限定名，运行时 ReferenceError。

最小输入 entry.ts:
  enum E { A = 1, B = A * 3 }
  console.log(E.A, E.B);

wake 产物（dist/bundle.js 第22-23行）:
  E[E["A"] = 1] = "A";
  E["B"] = A * 3;        <-- 裸 A

node 实际输出: ReferenceError: A is not defined  (at E, bundle.js:23:14)

tsc 7.0.2 对拍（--target es2022 --module commonjs）:
  E[E["A"] = 1] = "A";
  E[E["B"] = 3] = "B";   <-- 折叠并限定

真实世界影响：位标志 enum 这一极常见写法直接崩。
  enum Flags { None = 0, A = 1 << 0, B = 1 << 1, AB = A | B }
  -> 产物 Flags["AB"] = A | B;  -> ReferenceError: A is not defined
注意 A/B 各自能算出值（1<<0 不含裸引用），只有引用前序成员的 AB 崩，所以问题只在特定写法暴露。
```

**复现**：

```
1. mkdir <tmp>/t23 && cd <tmp>/t23
2. 写 entry.ts，内容完全如下（两行）:
   enum Flags { None = 0, A = 1 << 0, B = 1 << 1, AB = A | B }
   console.log("T1 flags:", Flags.A, Flags.B, Flags.AB);
3. 命令: C:/Users/zhang/Desktop/SourceCode/RustProject/wake/target/debug/wake.exe build entry.ts --outdir dist --sourcemap
   -> 构建成功 · 1 模块（无任何告警）
4. 命令: node dist/bundle.js

实际输出:
  ReferenceError: A is not defined
      at Flags (dist/bundle.js:25:19)

期望输出（tsc 7.0.2 同源码）:
  T1 flags: 1 2 3

产物对比 —— wake dist/bundle.js 第22-25行:
  Flags[Flags["None"] = 0] = "None";
  Flags["A"] = 1 << 0;
  Flags["B"] = 1 << 1;
  Flags["AB"] = A | B;
tsc 应为:
  Flags[Flags["AB"] = 3] = "AB";  （或 Flags.A | Flags.B 的限定形式）
```

### [B2] `high` · docs/TS-SYNTAX-SUPPORT.md 支持矩阵复核

**声明**：§2「enum ... 值语义 → IIFE ✅」隐含的正向/反向双向映射；§9 对比表「enum → IIFE wake ✅ / esbuild ✅ / SWC ✅」（与两者并列）

**实测**：

```
凡初始化器不是纯数字字面量的 enum 成员，wake 只发射正向赋值 E["X"] = v，丢掉反向映射 E[v] = "X"。构建成功、node 不报错，只是反查静默返回 undefined —— 静默错误结果，比崩溃更隐蔽。

输入 entry.ts:
  enum Level { Low = 1 << 0, Mid = 1 << 1, High = 1 << 2 }
  console.log("AB1 fwd:", Level.Low, Level.Mid, Level.High);
  console.log("AB2 REVERSE:", Level[1], Level[2], Level[4]);
  console.log("AB3 obj:", JSON.stringify(Level));

wake 产物: Level["Low"] = 1 << 0;  (缺外层 Level[...] = "Low")
tsc 7.0.2 产物: Level[Level["Low"] = 1] = "Low";

同源码运行结果并排:
  wake -> AB2 REVERSE: undefined undefined undefined
          AB3 obj: {"Low":1,"Mid":2,"High":4}
  tsc  -> AB2 REVERSE: Low Mid High
          AB3 obj: {"1":"Low","2":"Mid","4":"High","Low":1,"Mid":2,"High":4}

触发条件（实测 enum E1 { A=1, B=2*3, C=base, D="x".length, E }）：只有裸数字字面量成员 A 得到反向映射，B/C/D 全部丢失。tsc 对真正非常量成员也照样发射反向映射（对拍 enum X { A = "s".length, B = g } -> X[X["A"] = "s".length] = "A"），故这不是「常量折叠差异」，是缺失。

附带：auto-increment 在非字面量成员之后产出 E1["E"] = undefined（tsc 此处是编译错误），wake 静默给 undefined。
```

**复现**：

```
1. mkdir <tmp>/t30 && cd <tmp>/t30
2. entry.ts 内容:
   enum Level { Low = 1 << 0, Mid = 1 << 1, High = 1 << 2 }
   console.log("AB1 fwd:", Level.Low, Level.Mid, Level.High);
   console.log("AB2 REVERSE:", Level[1], Level[2], Level[4]);
   console.log("AB3 obj:", JSON.stringify(Level));
3. C:/Users/zhang/Desktop/SourceCode/RustProject/wake/target/debug/wake.exe build entry.ts --outdir dist --sourcemap
   -> 构建成功，零告警
4. node dist/bundle.js

实际输出:
  AB1 fwd: 1 2 4
  AB2 REVERSE: undefined undefined undefined
  AB3 obj: {"Low":1,"Mid":2,"High":4}

期望输出（tsc 7.0.2，node fixtures/react-ts-app/node_modules/typescript/lib/tsc.js --target es2022 --module commonjs 同一文件后运行）:
  AB1 fwd: 1 2 4
  AB2 REVERSE: Low Mid High
  AB3 obj: {"1":"Low","2":"Mid","4":"High","Low":1,"Mid":2,"High":4}
```

### [B5] `high` · M2 — 组件扫描 + 入口/HTML 生成（docs/CRUSTIFY-PARITY-PLAN.md 第 46-55 行）

**声明**：（第 49/53 行的兑现）`import pages from "@@@/{ns}"` 与 `import()` 懒加载在 `wake build` 产物中的实际返回值

**实测**：

```
根因：单包 emit 路径（incremental.rs ~2561-2571）已经意识到「minify 下省略 `__esModule` 标记」并改用 `'default' in m` 判定；但**分包 chunk 运行时**（incremental.rs ~3011-3013）仍硬编码 `function interopDefault(m){ return m && m.__esModule ? m.default : m; }` / `interopStar` 同款，而进入 chunk 的模块体只发 `exports.default = a;` 从不发 `__esModule`。后果：**任何产出 ≥2 个 chunk 的 `wake build`**，(a) `import X from './m.ts'` 拿到 `{default: 真值}` 而非真值；(b) `import('./m.ts')` 解析出 `{default: {default: 真值}}` 双层包裹。M2 的虚拟入口把应用代码强制变成 async chunk，所以**每个**无 entry 的 `wake build` 都命中。这直接废掉 `pages.map(...)` 和 `React.lazy(() => import(p))` 两种 crustify 招牌用法。单包构建（`wake build src/main.ts` 且无动态 import）与命名导入 `import { a } from`、`import * as ns from` 均**不受影响**。
```

**复现**：

```
【最小复现 A —— default import】
1) 目录 `audit-m2/p4/`，`package.json` = `{ "name":"p4" }`；
2) `src/list.ts`：`const items = [10, 20, 30];\nexport default items;`
3) `src/lazy.ts`：`export const lazy = "lazy";`（只为逼出第 2 个 chunk）
4) `src/main.ts`：
```ts
import items from "./list.ts";
import("./lazy.ts");
console.log("split-build default import ->", JSON.stringify(items), "isArray:", Array.isArray(items));
```
5) `wake.exe build src/main.ts` → `✓ 3 模块 · 2 chunk`
6) `node -e "require('./dist/'+require('./dist/manifest.json').entry)"`
实际输出：`split-build default import -> {"default":[10,20,30]} isArray: false`
期望输出：`split-build default import -> [10,20,30] isArray: true`
对照组：删掉第 3 行 `import("./lazy.ts")` 使产物只剩 1 个 chunk → 输出变为 `[10,20,30] isArray: true`（正确）。

【最小复现 B —— M2 主流程 + 懒加载双层包裹】
1) 目录 `audit-m2/p2/`（第 1 条 finding 的工程），`src/entry.tsx`：
```tsx
import pages from "@@@/pages";
console.log("entry ok", pages.length);
```
2) `wake.exe build`（无 entry）→ `✓ 8 模块 · 6 chunk`
3) `node -e "require('./dist/entry.8b69217d.js')"`
实际：`entry ok undefined`（`pages` 是 `{default:[…]}`，`.length` 为 undefined；写 `pages.map(...)` 直接 `TypeError: p.map is not a function`）。
期望：`entry ok 3`。
4) 再验证懒加载返回值：
```js
require('./dist/entry.8b69217d.js');
setTimeout(()=>{ globalThis.__PAGES__.default[0].component.then(m=>{
  console.log(typeof m.default, typeof m.default.default, m.default.default());
}); }, 400);
```
实际：`object function about` —— 即组件在 `m.default.default`。
期望：`function`（组件在 `m.default`，`React.lazy(()=>import(p))` 才能工作）。
```
