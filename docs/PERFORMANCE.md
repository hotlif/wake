# 性能与产物体积

更新日期：2026-07-28。

## 2k modules 基线

测试命令：

```powershell
cargo build --release -p wake_cli
cd fixtures/2k-modules
npm run bench
```

fixture 包含 2013 个模块。脚本预热后执行 5 次时间采样、2 次内存采样，并运行产物校验
checksum。产物报告同时包含 raw、Gzip level 9 和 Brotli quality 11。

## 第一轮体积优化结果

| 指标 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---:|
| Raw | 178,869 B | 178,448 B | -421 B |
| Gzip | 19,180 B | 19,096 B | -84 B |
| Brotli | 14,087 B | 14,038 B | -49 B |
| 平均构建时间 | 155 ms | 153 ms | 无可见回归 |
| 峰值内存 | 55 MB | 54 MB | 无可见回归 |

本轮只采用局部、可证明安全的优化：

- minify 模式下合法导出键使用点访问；
- 缩短单包生产 runtime 的内部变量；
- 保留任意字符串导出名的括号访问；
- benchmark 固化压缩体积与 wrapper 数量。

当前 Webpack raw 产物为 170,930 B，Wake 仍大 7,518 B（约 4.4%）。剩余差距不应继续通过
零散字符串缩短处理：Terser 二次压缩 Wake 产物仍可回收约 5.5 KB，说明主要问题是整个 bundle
层级的语句合并和跨 concat scope 压缩；另有 16 个模块 wrapper。下一轮应先加入 wrapper 拒绝原因
统计，再提高 ESM concat 覆盖率，并为“生成产物二次优化”设计独立 AST pass，避免在文本层做不安全
替换。

## 第二轮：第一、第二阶段验证

### 第一阶段：整包 AST 二次优化

曾在 linker `emit` 后重新解析整包，并执行已有简化 pass 后重新 codegen。正确性测试首先发现：
如果直接复用模块级 DCE，会删除仍被 linker 导出赋值引用的声明。将范围收缩到不含 DCE、变量折叠
和 mangle 后，111 项 bundler 测试通过，但 release 产物反而增加约 3.6 KB。原因是当前 codegen
会重新展开 linker 已经生成的紧凑文本。该实验实现已撤销。

结论：整包优化不能直接复用模块级 pipeline；需要保留符号与导出活跃信息的 Bundle IR，再在 IR
上做跨模块声明合并、变量折叠和最终 codegen。

### 第二阶段：空模块 wrapper 合并

2k fixture 的 16 个 wrapper 中有 12 个空 stub。实验让这些 ID 共用一个空执行函数，同时仍由
runtime 为每个 ID 创建独立 exports，语义测试 111/111 通过。release 结果如下：

| 指标 | 当前基线 | 共用空函数 | 变化 |
|---|---:|---:|---:|
| Raw | 178,448 B | 178,369 B | -79 B |
| Gzip | 19,096 B | 19,101 B | +5 B |
| Brotli | 14,038 B | 14,043 B | +5 B |
| wrapper | 16 | 4 | -12 |

重复的 `function(){}` 对 Gzip/Brotli 极易压缩，所以该方案虽减少 raw，却让两项压缩体积轻微
退化，实验实现已撤销。wrapper 不是当前 7.5 KB raw / 3.8 KB Gzip / 5.1 KB Brotli 差距的
主要来源。

下一阶段的主任务应是 Bundle IR：在模块链接之后、最终打印之前统一表示声明、引用、导出和模块
边界，再安全执行跨模块压缩。继续缩短 runtime 或删除 wrapper 无法达到“不大于 Webpack”的目标。

## 第三轮：DCE 与纯注册 sequence

进一步用 Terser 单项开关归因：仅启用 `unused` 可将基线从 178,448 B 降到 173,740 B，
而仅启用 `join_vars` 为 177,811 B。这说明主要缺口首先来自未使用值分析，而非变量名长度。

本轮落地：

- DCE 删除已解析局部绑定的无效果读取，但保留未解析全局读取（后者可能抛 `ReferenceError`）；
- 变量分析忽略已经由 DCE 计划删除的引用；
- linker 对无用 import 绑定只保留模块求值，不再生成本地绑定；
- 被 tree shaking 删除的导出不再无条件保活本地变量；
- 已确认只有 `globalThis.__reg` 副作用的 2,000 多个模块按原顺序组成单一 sequence。

2k fixture 的一次 release 精确结果：

| 指标 | 上轮基线 | 本轮 | 变化 |
|---|---:|---:|---:|
| Raw | 178,448 B | 178,292 B | -156 B |
| Gzip | 19,096 B | 19,076 B | -20 B |
| Brotli | 14,038 B | 14,023 B | -15 B |
| 分号数量 | 2,444 | 527 | -1,917 |

checksum 与运行输出一致，bundler 测试 111/111 通过。收益仍远小于 Terser `unused` 的理论
空间，剩余主要是“构造局部值 → 写入 exports → 随后的纯读取”链式折叠，需要能表达声明、导出写入
和纯表达式之间关系的链接级数据流分析。

## 第四轮：僵尸导出依赖链

链接级 tree shaking 原本能删除未使用的导出函数，却仍把这些函数体对 `_state`、`_listeners` 和内部
helper 的引用计入活跃集合，形成“导出已死、依赖仍活”的僵尸链。本轮将已有的迭代剪枝结果接入
普通顶层声明发射：

- 删除仅被已删除导出读取的简单顶层变量；
- 对 `new Set()`、函数调用、成员读取等可能有副作用或抛错的初始化器，只删除绑定并保留求值；
- 删除仅被已删除导出调用的本地 helper，以及只有自身递归引用的死导出函数；
- 活跃别名导出 `export { local as publicName }` 显式保护其本地绑定；
- 非导出语句中的真实读取会阻止删除；
- tree shaking 后不含任何作用域绑定的模块不再输出冗余隔离块。

2k fixture 的 release 精确结果：

| 指标 | 第三轮 | 第四轮 | 变化 |
|---|---:|---:|---:|
| Raw | 178,292 B | 174,319 B | -3,973 B |
| Gzip | 19,076 B | 18,315 B | -761 B |
| Brotli | 14,023 B | 13,458 B | -565 B |
| `const` | 121 | 67 | -54 |
| `let` | 65 | 12 | -53 |
| `function` | 71 | 62 | -9 |

Webpack 仍为 170,930 / 15,320 / 8,936 B；Wake raw 差距已缩小到 3,389 B（约 1.98%）。
剩余压缩后差距明显高于 raw 差距，后续除了继续做未使用值提取，还需要优化模块排列与重复文本的
压缩局部性。

## 第五轮：确定性排序与空 stub

`inline_regs` 原先直接遍历 `FxHashMap`，相似路径和编号的注册语句被随机打散。Raw 不受影响，但
压缩器无法在有限窗口内复用大量重复前缀。改为按 module id 稳定排序后，两次独立构建 SHA-256
一致，压缩体积大幅下降。

同时，空模块 stub 不再逐项输出 `id:function(){}`。runtime 在表项缺省时仍会按 id 创建并缓存
独立空 exports，只跳过模块函数调用，因此保持原有模块身份语义。

| 指标 | 第四轮 | 第五轮 | 变化 |
|---|---:|---:|---:|
| Raw | 174,319 B | 174,114 B | -205 B |
| Gzip | 18,315 B | 16,623 B | -1,692 B |
| Brotli | 13,458 B | 9,841 B | -3,617 B |
| wrapper | 17 | 4 | -13 |

对比 Webpack，当前差距约为 Raw 3,184 B、Gzip 1,303 B、Brotli 905 B。两个额外实验未保留：

- concat id 查表改用 `Set`：Raw -59 B、Gzip -2 B，但 Brotli +1 B；
- 删除 linker 生成代码的重复空格：Raw -120 B、Gzip -14 B，但 Brotli +31 B。

## 第六轮：无内部引用导出函数直写

此前 `export function foo(){}` 固定生成“具名声明 + 导出赋值”：
`function a(){};$.foo=a`。对于模块内从未读取函数名的导出，这个局部绑定没有用途。本轮将其直接
生成为 `$.foo=function(){}`，并采用保守的模块级读取集合保护递归函数和被其它声明引用的函数。
同名的嵌套绑定最多阻止优化，不会导致错误合并。

| 指标 | 第五轮 | 第六轮 | 变化 | Webpack | 当前差距 |
|---|---:|---:|---:|---:|---:|
| Raw | 174,114 B | 173,985 B | -129 B | 170,930 B | +3,055 B |
| Gzip -9 | 16,623 B | 16,553 B | -70 B | 15,320 B | +1,233 B |
| Brotli 11 | 9,841 B | 9,804 B | -37 B | 8,936 B | +868 B |

`cargo test --workspace` 全部通过；2k fixture 正式基准的正确性校验通过，Wake 平均 253 ms、
峰值内存 55 MB，Webpack 平均 8,054 ms、峰值内存 779 MB。

布尔常量的 `true/false → !0/!1` 实验未保留：虽然 Raw -59 B、Gzip -5 B，但 Brotli +27 B。
下一阶段应继续处理剩余约 3 KB 的链接后结构开销，优先分析活跃 store 模块中的变量声明、
导出赋值以及 concat redirect，而不是继续微调字面量拼写。

## 第七轮：纯注册段初始化消除与 registry 缓存

2k fixture 中约 2,000 个模块已被识别为无导出、无依赖的注册模块，但每个模块仍重复生成
`globalThis.__reg ||= {}`。本轮没有跨任意用户代码合并状态，而是进一步识别“初始化 + 单个数字属性
赋值”的精确模块体，并只在连续精确段内：

- 第一个模块初始化 registry 并缓存到局部变量 `q`；
- 后续模块直接生成 `q.name=value`；
- 遇到调用、声明或其它非精确非空模块体立即使缓存失效，下一段重新读取并初始化全局 registry；
- 合法的命名导入属性改用点访问，字符串导出名仍保留方括号访问。

| 指标 | 第六轮 | 第七轮 | 变化 | Webpack | 对比 |
|---|---:|---:|---:|---:|---:|
| Raw | 173,985 B | 68,637 B | -105,348 B | 170,930 B | -102,293 B |
| Gzip -9 | 16,553 B | 15,881 B | -672 B | 15,320 B | +561 B |
| Brotli 11 | 9,804 B | 8,733 B | -1,071 B | 8,936 B | -203 B |

正式基准正确性验证通过：Wake 平均 276 ms、峰值内存 53 MB，Webpack 平均 5,237 ms、
峰值内存 817 MB。`cargo test --workspace` 全部通过。

连续 linker `const` 合并实验未保留：Raw -70 B，但 Gzip +4 B、Brotli +49 B。Terser 单项
归因也显示单独 mangle 会使 Gzip/Brotli 变大；下一阶段应集中补齐语句压缩，而不是继续缩短变量名。
