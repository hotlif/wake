# 学习路线

这份文档面向第一次使用 Wake 的开发者。你不需要熟悉 Rust，也不需要提前了解打包器内部原理；只要会使用终端、能阅读基础的 TypeScript 和 React 代码，就可以按照页面顺序完成学习。你也不必一次读完全部内容，先选择最接近当前目标的入口：

| 你现在想完成什么 | 建议从哪里开始 | 完成后得到什么 |
| --- | --- | --- |
| 运行第一个 React 19 项目 | [快速开始](./quick-start) | 开发服务器、自动更新和 <code>dist</code> 生产产物 |
| 建立组件库文档 | [第一个文档站](./first-docs-site) | 中文 MDX 页面、隔离 Demo 和 Props API |
| 把 Wake 接入现有项目 | [开发与 HMR](../guide/development) | 监听、别名、代理和调试顺序 |
| 直接查询命令或错误 | [CLI 参考](../reference/cli) / [故障排查](../reference/troubleshooting) | 参数说明或按症状定位问题 |

## 先分清两个功能

Wake 包含两条彼此关联、但用途不同的工作流：

| 工作流 | 解决的问题 | 常用命令 |
| --- | --- | --- |
| 应用构建 | 开发和构建 React、TypeScript 应用 | `wake dev`、`wake build` |
| 组件文档 | 把 MDX、Demo 和 Props 类型生成文档站 | `wake docs dev`、`wake docs build` |

应用构建负责你的产品代码；Wake Docs 负责组件库的学习资料和交互示例。两者共享解析器、依赖解析、CSS、增量构建和生产优化，因此文档中的 Demo 与真实项目使用同一种编译行为。

## 开始前需要会什么

建议先确认以下基础概念：

- 知道 `package.json` 用来声明 npm 依赖和脚本；
- 知道 React 组件是返回 JSX 的函数；
- 知道 TypeScript 的 `interface` 或 `type` 可以描述 Props；
- 会在项目目录执行 `npm install` 和 npm scripts；
- 会根据错误信息找到文件名和行号。

如果其中某项还不熟悉，也可以继续。后续教程会给出完整文件，不要求你自己补全缺失代码。

## 推荐阅读顺序

### 阶段一：成功运行

1. 阅读[“快速开始”](./quick-start)，从源码编译 Wake 并运行最小 React 19 应用。
2. 阅读[“第一个文档站”](./first-docs-site)，创建 MDX 首页、组件 Demo 和主题文件。
3. 完成检查点：修改一段文字和一个按钮颜色，浏览器能自动更新。

这一阶段结束后，你应该知道项目根、入口文件、`wake.config.toml` 和输出目录分别是什么。

### 阶段二：理解日常开发

1. 阅读[“开发与 HMR”](../guide/development)，理解哪些文件会被监听、什么时候需要重启。
2. 阅读[“生产构建”](../guide/production)，学习哈希资源、公共路径和部署前检查。
3. 阅读[“配置参考”](../guide/configuration)，掌握路径别名、代理、浏览器目标和文档配置。

这一阶段结束后，你应该可以把 Wake 接入一个现有的 React 19 项目，并能定位常见的路径和端口问题。

### 阶段三：熟练编写组件文档

1. 阅读[“组件文档概览”](../docs/overview)，建立 MDX、Demo、Props 和生成模块的整体认识。
2. 阅读[“编写 MDX”](../docs/mdx)，学习 Frontmatter、代码高亮、自定义组件和静态属性规则。
3. 阅读[“Demo 与 Props API”](../docs/demo-api)，掌握隔离预览、元数据和 JSDoc。
4. 跟随[“Button 文档实战”](../docs/button-tutorial)完成一套组件页面。

这一阶段结束后，你应该能独立为新组件添加页面、多个 Demo 和 Props API，并能判断构建错误属于 MDX、模块解析还是类型提取。

### 阶段四：项目化使用

1. 阅读[“Crab UI 组件”](../guide/crab-components)，了解如何通过 npm 使用真实组件库。
2. 阅读[“CLI 参考”](../reference/cli)，把常用命令写进 CI 和 package scripts。
3. 阅读[“故障排查”](../reference/troubleshooting)，建立从症状到原因的排查顺序。
4. 阅读[“术语表”](../reference/glossary)，补齐构建工具常用概念。

## 三条最常用命令

```bash title="日常开发"
wake dev .
wake docs dev .
wake docs build . --outdir docs-dist
```

第一条启动应用，第二条启动组件文档，第三条生成可部署的静态文档目录。命令最后的点号表示“当前目录是项目根”。

## 如何判断自己已经熟练

完成下面的任务时不需要复制整个示例，就说明已经具备独立使用能力：

- 能解释 `@`、`@@` 和相对路径的区别；
- 能从零创建 React 19 入口并启动开发服务器；
- 能为文档设置标题、中文界面、主题色和部署子路径；
- 能写出一个包含 Frontmatter、Demo 和 API 的 MDX 页面；
- 能使用 `preview.tsx` 注入 Provider 和全局样式；
- 能通过 JSDoc 让 Props 表格出现说明、默认值和废弃信息；
- 能看懂带错误代码、文件路径和行列号的 Wake 诊断；
- 能在部署前用生产构建验证子路由和静态资源路径。

<Callout title="学习建议" tone="info">
不要一开始复制完整配置。先让最小项目运行，再逐项加入别名、代理、主题和组件扫描。每增加一项就重新构建一次，出现问题时更容易确定是哪项配置造成的。
</Callout>

## 遇到问题时的阅读顺序

先看终端最后一条 Wake 错误，再按下面顺序检查：

1. 文件是否存在、路径是否相对正确的项目根；
2. `package.json` 是否声明并安装了所需依赖；
3. `wake.config.toml` 是否是合法 TOML；
4. MDX 的 Frontmatter 和编译期组件属性是否为静态值；
5. 仍无法解决时，再查“故障排查”的对应症状。

准备好后，前往[快速开始](./quick-start)创建第一个 React 19 项目；如果你只关心组件库文档，也可以直接进入[第一个文档站](./first-docs-site)。
