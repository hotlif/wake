这一章不再分别讲概念，而是按真实工作顺序完成一套 Button 文档。建议新建练习分支并亲手输入关键文件。

## 第一步：实现组件

```tsx title="src/button.tsx"
import type {
  ButtonHTMLAttributes,
  ReactNode,
} from "react";

export type ButtonAppearance =
  | "primary"
  | "secondary"
  | "danger";

export interface ButtonProps
  extends Omit<ButtonHTMLAttributes<HTMLButtonElement>, "children"> {
  /** 按钮内容 */
  children: ReactNode;

  /** 按钮外观
   * @default "primary"
   */
  appearance?: ButtonAppearance;

  /** 是否显示处理中状态
   * @default false
   */
  loading?: boolean;

  /** 是否占满容器宽度
   * @default false
   */
  block?: boolean;
}

export function Button({
  children,
  appearance = "primary",
  loading = false,
  block = false,
  disabled,
  style,
  ...rest
}: ButtonProps) {
  return (
    <button
      {...rest}
      data-appearance={appearance}
      disabled={disabled || loading}
      aria-busy={loading || undefined}
      style={{
        width: block ? "100%" : undefined,
        ...style,
      }}
    >
      {loading ? "处理中…" : children}
    </button>
  );
}
```

注意三个设计点：

1. Props 类型是导出的稳定名称；
2. 默认值同时出现在 JSDoc 和实现中；
3. loading 会影响 `disabled` 和 `aria-busy`，不仅替换文字。

## 第二步：添加组件样式

```css title="src/button.css"
button[data-appearance] {
  min-height: 40px;
  padding: 0 16px;
  border: 1px solid transparent;
  border-radius: 8px;
  font: inherit;
  cursor: pointer;
}

button[data-appearance="primary"] {
  color: white;
  background: #7c3aed;
}

button[data-appearance="secondary"] {
  color: #18181b;
  border-color: #d4d4d8;
  background: white;
}

button[data-appearance="danger"] {
  color: white;
  background: #e11d48;
}

button[data-appearance]:disabled {
  cursor: not-allowed;
  opacity: .55;
}
```

在组件或 Preview 中导入样式。组件库通常从组件入口导入，练习项目可以在 `docs/preview.tsx` 中导入。

## 第三步：创建基础 Demo

```tsx title="docs/button/demos/basic.demo.tsx"
import React from "react";
import { Button } from "../../../src/button";

export const meta = {
  title: "基础用法",
  description: "最常见的主要操作",
};

export default function BasicDemo() {
  return (
    <Button onClick={() => window.alert("保存成功")}>
      保存设置
    </Button>
  );
}
```

Demo 中使用真实动作文字“保存设置”，比“确定”更能表达组件使用原则。

## 第四步：创建外观 Demo

```tsx title="docs/button/demos/appearance.demo.tsx"
import React from "react";
import { Button } from "../../../src/button";

export const meta = {
  title: "按钮外观",
  description: "按操作优先级选择外观",
  padding: "lg",
};

export default function AppearanceDemo() {
  return (
    <div style={{ display: "flex", flexWrap: "wrap", gap: 12 }}>
      <Button appearance="primary">保存</Button>
      <Button appearance="secondary">取消</Button>
      <Button appearance="danger">删除</Button>
    </div>
  );
}
```

不要只展示颜色，还要用合适的动作文字表达不同语义。

## 第五步：创建状态 Demo

```tsx title="docs/button/demos/loading.demo.tsx"
import React from "react";
import { Button } from "../../../src/button";

export const meta = {
  title: "加载与禁用",
  description: "防止操作被重复提交",
  background: "muted",
};

export default function LoadingDemo() {
  return (
    <div style={{ display: "flex", gap: 12 }}>
      <Button loading>正在保存</Button>
      <Button disabled>没有权限</Button>
    </div>
  );
}
```

加载状态要保留动作上下文，不要把所有按钮都变成含义模糊的“Loading”。

````mdx title="docs/button/index.mdx"
# Button 按钮

Button 用于提交、确认或触发一次即时操作。

## 基础用法

<Demo src="./demos/basic.demo.tsx" />

## 什么时候使用

- 用户主动触发操作；
- 操作结果明确；
- 操作完成后能立即反馈。

## 什么时候不要使用

- 页面之间跳转优先使用链接；
- 多项选择优先使用 Checkbox 或 Select；
- 长时间后台任务应配合进度反馈。

## 外观与状态

<Demos glob="./demos/*.demo.tsx" columns={2} />

## 无障碍

仅图标按钮必须提供可理解的 aria-label。加载时应设置
aria-busy，并阻止重复提交。

## API

<API
  source="../../src/button.tsx"
  symbol="ButtonProps"
  component="Button"
/>
````

基础 Demo 会被 `<Demo>` 展示一次，也会被 `Demos` glob 再匹配一次。真实页面可把 glob 改成更具体的命名规则，或只保留 `<Demos>`，避免重复。

## 第七步：配置 Preview

```tsx title="docs/preview.tsx"
import React from "react";
import "../src/button.css";

export default function Preview({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <div style={{
      minHeight: 96,
      display: "grid",
      placeItems: "center",
    }}>
      {children}
    </div>
  );
}
```

如果组件库发布独立 CSS，应改为从 npm CSS 子路径导入。这能验证消费者真正需要的安装方式。

## 第八步：开发验证

```bash
wake docs dev .
```

依次完成：

1. 打开 Button 页面；
2. 点击基础 Demo；
3. 切换源码并复制；
4. 切换手机宽度，确认按钮没有横向溢出；
5. 切换暗色主题，检查对比度；
6. 在 API 过滤框输入 `loading`；
7. 修改 `loading` 的 JSDoc 并保存；
8. 新增一个 Demo，确认注册表自动更新。

<Callout title="调试方法" tone="info">
如果页面能打开但 Demo 失败，先检查 Demo 导入和 Preview；如果整个文档生成失败，先检查 MDX 静态路径和 API symbol。把问题按阶段拆开会比同时修改多个文件更快。
</Callout>

## 第九步：生产验证

```bash
wake docs build . --outdir docs-dist
```

构建成功后检查：

- `docs-dist/components/button/index.html` 存在；
- `404.html` 存在；
- 页面 JS 是异步 chunk；
- 样式文件带 hash；
- `manifest.json` 包含 Button 页面；
- `draft = true` 的实验页没有输出；
- 使用计划中的部署 `base_path` 打开资源不会 404。

## 进阶练习

- 添加仅图标按钮，要求 `aria-label`；
- 给 `appearance` 添加废弃值并写 `@deprecated`；
- 用 `Pick<ButtonProps, "appearance" | "loading">` 创建子类型；
- 增加一个超长中文按钮文字 Demo；
- 在 Preview 中实现业务 ThemeProvider；
- 把 Button 替换为 npm 发布的 `@crab-dev/rc-button`。

完成这些练习后，你已经覆盖新增组件文档最常见的工作流程。下一次新增组件时，可以直接复用“组件源码 → 样式 → Demo → MDX → API → 开发验证 → 生产验证”这一顺序。
