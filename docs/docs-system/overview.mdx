# 组件文档概览

Wake Docs 把组件说明、可运行示例和 TypeScript Props 放进同一个可搜索站点。它不是独立模板工具，而是 Wake 的原生构建模式：MDX 最终生成 TSX，Demo 与业务组件继续由 Wake 编译。

## 适合什么项目

Wake Docs 当前适合：

- React 19 或更高版本的组件库；
- 希望文档与组件源码放在同一仓库的团队；
- 需要交互 Demo、源码查看和 Props 表格的设计系统；
- 希望产出纯静态文件，不维护文档服务端的项目。

首版不覆盖 Vue、Svelte、React Server Components，也不接受不可信用户上传的 MDX。

## 最小组成

一个可运行的文档站至少需要：

| 文件 | 是否必需 | 职责 |
| --- | --- | --- |
| `package.json` | 是 | 声明 React 19、React DOM 和项目组件依赖 |
| `wake.config.toml` | 建议 | 指定标题、中文界面、文档目录和主题 |
| `docs/index.mdx` | 是 | 至少提供一个页面 |
| `*.demo.tsx` | 否 | 提供交互预览与源码 |
| `preview.tsx` | 否 | 为所有 Demo 注入 Provider 和全局样式 |
| `theme.css` | 否 | 覆盖文档站品牌外观 |
| 组件 `.tsx` | 使用 API 时必需 | 提供真实实现和 Props 类型 |

推荐结构：

```text
my-library/
├─ docs/
│  ├─ index.mdx
│  ├─ components/
│  │  ├─ button.mdx
│  │  └─ demos/
│  │     ├─ basic.demo.tsx
│  │     └─ loading.demo.tsx
│  ├─ preview.tsx
│  └─ theme.css
├─ public/
│  └─ logo.svg
├─ src/
│  └─ button.tsx
├─ package.json
└─ wake.config.toml
```

## 一篇页面是怎样生成的

```text
button.mdx
  → markdown-rs 解析 MDX AST
  → 校验 Frontmatter、Demo、Demos、API
  → 生成 .wake/docs/generated/pages/button.tsx
  → Wake 编译 TSX、依赖和 CSS
  → 浏览器按路由懒加载页面 chunk
```

生成目录 `.wake/docs/generated` 是中间产物。它同时服务开发和生产，以避免两套模板逻辑产生差异。

## 页面、Demo 和 API 的关系

假设 `button.mdx` 中写了：

```mdx
<Demo src="./demos/basic.demo.tsx" />
<API source="../../src/button.tsx" symbol="ButtonProps" component="Button" />
```

Wake 会分别执行：

1. 把 MDX 正文编译成页面；
2. 把 Demo 建成独立模块，并生成可复制的源码模块；
3. 从 `button.tsx` 读取 `ButtonProps`，生成结构化 API 数据；
4. 把页面标题、描述、标题节点和 Props 名称加入搜索索引；
5. 在浏览器进入 Button 路由时按需加载页面和 Demo。

因此修改 Demo 不需要重写 MDX，修改 JSDoc 也不需要手工维护 Props 表格。

## 开发模式监听什么

```bash
wake docs dev . --port 5173
```

| 修改内容 | 预期更新 |
| --- | --- |
| MDX 正文 | 当前页面与搜索/目录数据 |
| 新增或删除 MDX | 路由、侧栏和搜索索引 |
| Demo 源码 | 对应 Demo chunk 和源码视图 |
| Props 类型或 JSDoc | 对应 API 数据 |
| `preview.tsx` | 所有 Demo 的公共包装 |
| `theme.css` | 文档站主题样式 |
| 项目 `src` | 受影响的组件和依赖 |
| 文件重命名 | 重新扫描路由和 Demo 注册表 |

发生变化时，Wake 先更新必要的生成模块，再让共享 BuildSession 失效。正常情况下不需要手动删除 `.wake`。

## 生产构建会生成什么

```bash
wake docs build . --outdir docs-dist
```

生产模式会：

- 排除 `draft = true` 页面；
- 进行代码分割、Tree Shaking 和压缩；
- 抽取 CSS，给资源添加内容 hash；
- 复制 `public/`；
- 为每条文档路由生成 HTML 外壳；
- 生成根目录 `404.html` 和 `manifest.json`。

每条路由的 HTML 外壳包含该页面自己的标题、描述和语言标记。静态托管直接访问子路由时，仍能得到正确的浏览器标题。

## 运行时界面

文档运行时提供：

- 桌面三栏、平板两栏和移动抽屉；
- light、dark、system 主题，偏好写入 `localStorage`；
- `Ctrl+K` 或 `⌘K` 全局搜索；
- 页面目录与前后页导航；
- Demo 预览、源码复制、宽度预设和全屏模式；
- Props 过滤、继承分组和移动端卡片布局；
- 遵循 `prefers-reduced-motion` 的短动画。

通用运行时只依赖项目中的 React 19 和 React DOM。项目可以在 `docs/site` 或 MDX 自定义组件中使用自己的 UI 库，但不应把该 UI 库写死进 Wake Docs 核心。

## 路径的三个基准

新手最容易混淆以下路径：

| 场景 | 相对谁解析 |
| --- | --- |
| `[docs].source_dir`、`preview`、`theme_css` | 项目根 |
| MDX 的普通 `import` | 当前 MDX 文件 |
| `Demo.src`、`Demos.glob`、`API.source` | 当前 MDX 文件 |
| `public/` 中 `/logo.svg` | 文档站的 `base_path` |

建议先在编辑器中从当前 MDX 文件手工走一遍目录层级，再填写 `../`。

<Callout title="源码信任边界" tone="warning">
完整 MDX 支持 JavaScript 表达式和 ESM，因此本质上可以执行代码。只编译仓库中经过审核的文档源码，不要把用户上传内容直接交给 Wake Docs。
</Callout>

## 推荐的新增组件流程

每添加一个组件，按固定顺序操作：

1. 先完成组件实现和导出的 Props 类型；
2. 添加最小的基础 Demo，确认组件能运行；
3. 创建 MDX，说明用途和不适用场景；
4. 添加边界状态 Demo，例如禁用、加载、空数据和错误；
5. 加入 `<API>` 并检查 JSDoc；
6. 用键盘、窄屏和明暗主题检查；
7. 执行生产构建后再提交。
