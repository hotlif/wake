# 构建与部署 Wake Docs

<ResultPanel title="可以发布的静态文档目录" label="完成效果">
文档站从静态托管地址可直接访问，搜索、深层页面、Demo iframe 和聚合工作台使用正确前缀。
</ResultPanel>

## 生产构建

```bash
npx wake docs build . --outdir docs-dist
```

该命令完整编译站点。开发时尚未访问的页面依赖也会被检查，因此不能只用开发首页可用判断可发布。构建成功后再处理产物，失败时不要把保留的旧目录误认作本次结果。

## 部署

部署到 `/handbook/` 时配置 `[docs].base_path = "/handbook/"`，或本次构建使用 `--base /handbook/`。站点静态目录必须映射到同一前缀，链接、搜索结果、Demo 与工作台路径一起验证。

Wake 为文档路径生成静态页面。按托管环境配置目录 index 与 404 行为，不把普通应用的任意 history 回退规则照搬到所有文档资源。自定义组件使用提供的 href，避免顶栏写死 `/`。

## 放进 CI

```json title="package.json 中的脚本"
{
  "docs:dev": "wake docs dev .",
  "docs:build": "wake docs build . --outdir docs-dist"
}
```

CI 执行不可变安装、项目类型检查及 docs:build。按团队需要加入链接、拼写或内容格式检查。

## 验收

检查首页、两层以上页面直接访问、中文路径、章节链接、搜索选择、404、明暗主题、窄屏导航、Demo 操作及源码。使用 UI 覆盖时检查 Provider 和 Portal，聚合站点检查所有工作台而不仅是主站首页。

HTML 与搜索数据应及时更新，带哈希资源可长期缓存。上传完整输出目录，保留上一份完整发布用于回退；不发布源码安装树和 `.wake`。

## 常见错误

- 首页可用、Demo 404：检查 iframe 地址是否包含正确 base_path，以及资源是否完整上传。
- 子路径跳回域名根：检查自定义 href 和手写公开资源 URL。
- 生产才报告依赖错误：完整构建会触达未访问页面，按源码诊断修复。
