## 页面模板

```mdx
+++
title = "Live Reload"
description = "定位整页自动刷新链路"
kind = "guide"
status = "stable"
+++

# Live Reload

## 什么时候使用

正文从这里开始。
```

`kind` 支持 `overview`、`tutorial`、`guide`、`reference` 和 `component`。Frontmatter 只描述页面自身，导航位置由 `navigation.toml` 决定。

## 可用内容

普通段落、列表、表格、任务列表、代码围栏、链接和静态 JSX 都会编译成 React。导入语句必须位于 Frontmatter 后、正文前。

块组件会作为独立内容显示，文字和行内 JSX 保留在段落中。组件内部的 Markdown 仍会生成正常段落；Wake 会处理块元素的结构，无需手动用 HTML 段落包住卡片或示例。

## 编译期组件

`<Demo>`、`<Demos>` 和 `<API>` 的路径、glob、symbol 等属性必须是静态字面量。Wake 在构建前收集它们，动态表达式会得到带行列的诊断。

## 组织一篇可维护的页面

标题和 description 用于识别页面和搜索。先写读者要完成的任务，再给带文件名的代码块；同一配置只解释一次，完整字段链接参考区。站点目录从章节标题生成，因此标题应说明内容，不用“步骤一”替代真实含义。

代码围栏可以写语言和 `title="文件名"`。MDX 中 import 的组件是普通项目依赖，会参与构建；只导入实际使用的组件。不要把 shell 命令的占位文本伪装成可直接执行的完整脚本。

新增页面后同时验证导航引用、相对 Demo/API 路径及部署后的链接。MDX 路径属性相对当前页面，而不是始终相对项目根。

## 验证方式

运行 `wake docs dev`，检查标题、面包屑、右侧目录和搜索结果。再运行生产构建验证直接路由。

## 常见错误

- 不要用 Frontmatter 控制路由或导航顺序；这些职责分别属于文件路径和 `navigation.toml`。
- 不要在编译期组件属性中使用动态表达式。
