# 开发与 HMR

开发模式的目标是缩短“修改—看到结果—继续修改”的循环。Wake 会保持 BuildSession 常驻，并只让受变化影响的模块失效。

## 应用和文档使用不同命令

```bash title="React 应用"
wake dev . --port 5173
```

```bash title="组件文档"
wake docs dev . --port 5173
```

两个命令不能同时占用同一个端口。如果需要同时开发应用和文档：

```bash
wake dev . --port 5173
wake docs dev . --port 5174
```

分别在两个终端执行。

## 启动时发生什么

普通应用开发：

1. 从指定 ROOT 向上寻找 `wake.config.toml` 或 `package.json`；
2. 解析项目根、入口、别名和浏览器目标；
3. 更新组件扫描生成模块；
4. 创建 BuildSession 并完成第一次构建；
5. 启动 HTTP 与 HMR WebSocket；
6. 监听源码和额外目录。

文档开发还会先扫描 MDX、Demo 和 API 类型，生成 `.wake/docs/generated`，然后把生成入口交给同一构建会话。

## 开发模式与生产模式的差异

| 行为 | `wake dev` | `wake build` |
| --- | --- | --- |
| `NODE_ENV` | development | production |
| 进程 | 常驻 | 默认构建后退出 |
| 文件监听 | 是 | 仅 `--watch` 时 |
| HMR 连接 | 是 | 否 |
| 压缩与 mangle | 否 | 是 |
| Tree Shaking | 不按生产口径 | 是 |
| 输出重点 | 调试反馈 | 缓存和体积 |

开发正常不代表生产一定成功。提交前仍要执行一次生产构建。

## 开发服务器配置

```toml title="wake.config.toml"
[dev_server]
server = "http"
host = "127.0.0.1"
port = 5173
open = false
```

| 字段 | 说明 |
| --- | --- |
| `server` | 当前推荐 `http` |
| `host` | `127.0.0.1` 只允许本机访问；局域网调试需显式设置可监听地址 |
| `port` | Wake Docs 在没有 CLI 参数时使用该值 |
| `open` | 启动后是否自动打开浏览器 |
| `proxy` | API 转发规则数组 |

普通 `wake dev` 的 `--port` 有 5173 默认值，因此配置端口不会覆盖它。需要其他端口时显式传 `--port`。`wake docs dev` 的 port 是可选参数，优先级为 CLI、配置、5173。

## 什么变化会自动更新

| 变化 | 应用开发 | 文档开发 |
| --- | --- | --- |
| TS/TSX/JS/JSX | 重编受影响模块 | 同左 |
| CSS | 更新相关样式产物 | 同左 |
| 图片与资源 | 更新引用模块 | 同左 |
| MDX | 不适用 | 更新页面、目录与索引 |
| Demo | 不适用 | 更新 Demo chunk 和源码 |
| Props/JSDoc | 组件模块变化 | 更新 API 数据 |
| 新增/删除组件扫描文件 | 更新扫描模块 | 更新扫描模块 |
| `preview.tsx` | 不适用 | 更新所有 Demo 包装 |
| `theme.css` | 不适用 | 更新文档主题 |

配置文件本身发生结构变化时，最稳妥的做法是停止并重新启动命令，因为入口、监听根或端口可能已经改变。

## HMR 没更新时怎么做

按成本从低到高处理：

1. 确认保存的是当前项目内的文件；
2. 查看终端是否收到文件变化；
3. 查看页面是否出现编译错误覆盖层；
4. 手动刷新浏览器，区分 HMR 问题和构建问题；
5. 重新启动开发命令；
6. 最后才删除可再生成的 `.wake`。

不要一遇到问题就删除 `node_modules`。模块解析错误通常可以从第一条诊断找到更具体的包名或路径。

## API 代理

前端请求 `/api`，后端运行在 8080：

```toml title="wake.config.toml"
[[dev_server.proxy]]
context = ["/api"]
target = "http://127.0.0.1:8080"
change_origin = true
ws = false

[dev_server.proxy.path_rewrite]
"^/api" = ""
```

请求 `/api/users` 会匹配 context，路径改写后转发为后端 `/users`。

字段说明：

- `context` 可以列出多个路径前缀；
- `target` 必须包含协议和端口；
- `change_origin` 适合对 Host 有要求的服务；
- `path_rewrite` 的键是正则字符串；
- 文档开发服务器当前只转发 HTTP，`ws = true` 会输出不支持的警告。

代理只用于开发。生产环境的 `/api` 应由真实网关、反向代理或同源服务处理。

## 路径别名

Wake 内置：

| 别名 | 目标 | 示例 |
| --- | --- | --- |
| `@` | `<root>/src` | `@/button` |
| `@@` | 项目根 | `@@/docs/theme.css` |
| `@@@/<namespace>` | 组件扫描生成模块 | `@@@/ui` |

自定义别名：

```toml
[alias]
"@shared" = "src/shared"
"@assets" = "src/assets"
```

```ts
import { formatDate } from "@shared/date";
import logoUrl from "@assets/logo.svg";
```

自定义配置与内置别名同名时，自定义值优先。别名目标相对项目根解析。

## 组件自动扫描

```toml
[[component_scan]]
namespace = "ui"
cwd = "src/components"
include = "\\.(tsx|ts)$"
exclude = "\\.(test|spec)\\."
generate_source = false
```

Wake 扫描后生成 `.wake/scan/ui.ts`，项目通过保留别名加载：

```ts
const components = await import("@@@/ui");
```

参数：

| 字段 | 说明 |
| --- | --- |
| `namespace` | 生成模块名称，也是导入后缀 |
| `cwd` | 相对项目根的扫描目录 |
| `include` | 文件包含正则字符串 |
| `exclude` | 文件排除正则字符串 |
| `generate_source` | 是否把源码字符包含进扫描结果 |

新增、删除和重命名文件时，会先更新扫描模块再触发 BuildSession 失效。

<Callout title="生成目录" tone="info">
`.wake` 保存入口、扫描模块、Docs 生成文件和可选缓存。它可以删除后重建，应加入 `.gitignore`，也不应存放业务源码。
</Callout>

## 开发时的推荐终端布局

- 终端一：`wake docs dev . --port 5173`；
- 终端二：组件测试或类型检查；
- 终端三：按需运行 `wake docs build`；
- 浏览器：文档页面和控制台。

出现错误时保留第一条失败输出。后续连锁错误往往只是同一个根因造成的噪声。

## 新手调试练习

1. 故意把一个 import 路径改错，观察诊断中的发起文件和依赖名；
2. 恢复后把 MDX 的 Demo 路径改成变量，观察静态属性错误；
3. 恢复后新增 Demo，确认无需重启；
4. 修改 `wake.config.toml` 的端口并重启，确认地址变化；
5. 执行生产构建，比较开发和生产输出。

完成这些练习后，你会更熟悉 Wake 错误发生在哪个阶段，而不只是记住命令。
