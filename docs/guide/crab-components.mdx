# Crab UI 组件

当前 Wake 中文文档站的项目级界面使用 <code>@crab-dev/*</code> npm 包。组件源码来自 crab-dev 仓库的 <code>components</code> 目录，但本站构建只消费正式发布到 npm 的包，不从任何本机绝对路径导入。这样看到的导入、样式和依赖问题，才与真实使用者一致。

<Callout title="先记住三条规则" tone="success">
组件代码和 CSS 要分别导入；当前包要求 React 19；Crab UI 只属于这个文档项目，不能成为 Wake Docs 通用运行时的依赖。后面的安装、主题和 Demo 都围绕这三个边界展开。
</Callout>

<CrabComponentShowcase />

## 为什么使用 npm 包

从 npm 消费组件可以验证真实用户会遇到的环境：

- package exports 是否正确；
- ESM、CommonJS 和类型声明是否完整；
- CSS 子路径是否可解析；
- 运行时依赖是否都已声明；
- React peer 版本是否兼容；
- CI 和其他开发者电脑是否能重复安装。

直接导入本机源码会绕过发布包问题，也会使 CI、Linux 和其他目录结构无法构建。

## 当前站点锁定的包

| 包 | 版本 | 在文档站中的用途 |
| --- | --- | --- |
| `@crab-dev/rc-button` | `0.0.2` | 首页主操作和示例操作 |
| `@crab-dev/rc-card` | `0.0.2` | 首页能力卡片和组件展示 |
| `@crab-dev/rc-tag` | `0.0.2` | 状态、序号和版本标签 |
| `@crab-dev/rc-alert` | `0.0.2` | MDX 提示块 |
| `@crab-dev/rc-prose` | `0.0.2` | 长文本和提示内容排版 |
| `@linaria/core` | `8.1.1` | 当前发布包实际需要的 `cx` 运行时 |

React 和 React DOM 最低主版本为 19。

## 安装

```bash title="npm"
npm install \
  @crab-dev/rc-alert@0.0.2 \
  @crab-dev/rc-button@0.0.2 \
  @crab-dev/rc-card@0.0.2 \
  @crab-dev/rc-prose@0.0.2 \
  @crab-dev/rc-tag@0.0.2 \
  @linaria/core@8.1.1
```

PowerShell 可以写成一行：

```powershell title="Windows PowerShell"
npm install @crab-dev/rc-alert@0.0.2 @crab-dev/rc-button@0.0.2 @crab-dev/rc-card@0.0.2 @crab-dev/rc-prose@0.0.2 @crab-dev/rc-tag@0.0.2 @linaria/core@8.1.1
```

安装后确认：

```powershell
Get-ChildItem node_modules/@crab-dev
```

项目应提交 `package-lock.json`，不要提交 `node_modules`。

<Callout title="当前发布依赖问题" tone="warning">
Crab UI 0.0.2 的 ESM 会导入 <code>@linaria/core</code>，但各组件包尚未把它声明为运行时 dependency，因此消费者需要暂时显式安装 <code>@linaria/core@8.1.1</code>。组件包修正发布清单后应移除这项工作区直接依赖并重新验证。
</Callout>

## 导入规则

每个组件包含：

- `esm/index.mjs`；
- `cjs/index.cjs`；
- `declarations/index.d.ts`；
- `css/index.css`；
- package exports 映射。

Wake 会识别 `@crab-dev/rc-*` 的 npm 入口，并把该组件及其传递依赖的
`css/index.css` 自动加入模块图。业务代码只导入组件：

```tsx title="docs/site/components.tsx"
import Alert from "@crab-dev/rc-alert";
import Button from "@crab-dev/rc-button";
import Card from "@crab-dev/rc-card";
import Prose from "@crab-dev/rc-prose";
import Tag from "@crab-dev/rc-tag";

```

依赖组件的样式排在前面，当前组件样式排在后面；开发模式继续使用样式注入，生产构建继续抽取为带 hash 的 CSS。使用其他打包器时，应采用该组件库提供的自动样式插件，或按其说明手动导入 CSS。

## Button

```tsx
<Button appearance="primary" size="large">
  保存设置
</Button>

<Button
  appearance="danger"
  loading={saving}
  onClick={removeItem}
>
  删除
</Button>

<Button
  href="/getting-started/quick-start"
  appearance="subtle"
>
  阅读教程
</Button>
```

常用属性：

| 属性 | 值 | 说明 |
| --- | --- | --- |
| `appearance` | primary/subtle/dashed/text/link/danger | 视觉层级 |
| `size` | large/middle/small | 尺寸 |
| `loading` | boolean | 防止重复点击并显示加载 |
| `icon`、`iconAfter` | ReactNode | 前后图标 |
| `href` | string | 存在时渲染链接 |
| `shouldFitContainer` | boolean | 占满容器 |
| `isSelected` | boolean | 工具栏选中状态 |
| `shape` | circle | 圆形图标按钮 |

没有 children 的图标按钮必须提供 `aria-label`。

## Card

```tsx
<Card
  variant="outlined"
  size="large"
  title="构建结果"
  extra={<Tag color="success">成功</Tag>}
  actions={[
    <Button key="details" appearance="subtle">详情</Button>,
  ]}
>
  29 个模块在 423ms 内完成。
</Card>
```

`variant` 支持 elevated、outlined、filled。`hoverable` 只增加悬浮反馈；`clickable` 才让整卡获得键盘激活和 button role。整卡可点击时仍应避免把多个复杂交互嵌套在卡片内部。

Card 还提供复合结构：

```tsx
<Card>
  <Card.Header title="标题" />
  <Card.Body>内容</Card.Body>
  <Card.Footer>操作</Card.Footer>
</Card>
```

## Tag

```tsx
<Tag color="primary">React 19</Tag>
<Tag color="success">稳定</Tag>
<Tag color="warning">Beta</Tag>
<Tag color="error" closable onClose={removeTag}>
  构建失败
</Tag>
```

预设颜色是 default、primary、success、warning、error，也可以传入自定义颜色字符串。标签用于分类和短状态，不应用来承载长句。

## Alert

```tsx
<Alert
  type="warning"
  title="升级提示"
  showIcon
  action={<Button size="small">查看迁移</Button>}
>
  React 18 项目需要先升级到 React 19。
</Alert>
```

`type` 支持 success、info、warning、error。提示应包含用户下一步可以做什么；错误提示不要只有“失败”。

## Prose

```tsx
<Prose as="article" size="base">
  <h2>组件说明</h2>
  <p>这里可以放 Markdown 编译后的长文本。</p>
</Prose>
```

`size` 支持 sm、base、lg、xl；`as` 支持 div、article、section、main；`invert` 可独立使用暗色排版。Wake 文档站通过语义变量让 Prose 跟随站点主题，通常不需要手工设置 invert。

## 在 Wake Docs 中建立适配层

推荐把组件库依赖集中在 `docs/site`：

```text
docs/site/
├─ components.tsx   MDX 可复用组件
├─ preview.tsx      Demo Provider 和 CSS
└─ theme.css        Wake 与 Crab UI 的主题映射
```

MDX 只导入项目级包装：

```mdx
import { Callout } from "../site/components.tsx"

<Callout title="注意" tone="warning">
不要在输出目录保存源码。
</Callout>
```

这样升级包版本、修改设计令牌或替换组件时，不需要批量改所有 MDX。

## 主题变量映射

Crab UI CSS 使用 `--token-semantic-*` 并提供 fallback。文档站应把这些变量映射到 Wake 主题：

```css title="docs/site/theme.css"
:root {
  --token-semantic-color-background-surface: var(--surface);
  --token-semantic-color-background-hover-subtle: var(--surface-muted);
  --token-semantic-color-border-default: var(--border);
  --token-semantic-color-border-hover: var(--border-strong);
  --token-semantic-color-brand-primary: var(--wake-accent);
  --token-semantic-color-text-primary: var(--text);
  --token-semantic-color-text-secondary: var(--text-soft);
  --token-semantic-color-text-on-brand: #fff;
}
```

变量值继续引用 Wake 的 `--surface`、`--text` 等，因此 `data-theme` 切换时自动更新，不必重复两套 Crab UI 覆盖。

## 在 Demo 中使用 npm 组件

```tsx title="docs/button/demos/crab-button.demo.tsx"
import React from "react";
import Button from "@crab-dev/rc-button";

export const meta = {
  title: "npm 发布包",
  description: "验证消费者入口和样式",
};

export default function CrabButtonDemo() {
  return (
    <Button appearance="primary">
      来自 npm 的按钮
    </Button>
  );
}
```

这就是 Wake 中的最小消费者代码。Button 及其依赖组件的样式由 Wake 自动发现，Demo 和 Preview 都不需要重复导入。

## 新增另一个 Crab UI 包

例如接入 Drawer：

1. 从 npm 确认最新版本和 React peer；
2. 检查 package exports 和 CSS 子路径；
3. 安装并更新锁文件；
4. 在 `docs/site` 或 Demo 只导入组件；
5. 检查它的运行时依赖是否完整；
6. 用 Wake Docs 开发模式验证；
7. 执行生产构建；
8. 检查明暗主题、键盘和移动端；
9. 在本文的包表格与映射中记录用途。

如果包不是 `@crab-dev/rc-*`，Wake 不会猜测它的样式入口；此时遵循该包自己的导入说明。

## 依赖分层

| 层级 | Crab UI 依赖 |
| --- | --- |
| `wake_docs` 生成器 | 无 |
| Wake Docs 通用运行时 | 无，只依赖 React 19 |
| 当前项目 `docs/site` | 有，通过 npm |
| 业务 Demo | 按项目需要 |
| Crab UI 源码仓库 | 只用于开发和发布包 |

这种分层既让当前站点真实使用 Crab UI，也不会强迫所有 Wake 用户安装它。

<Callout title="禁止绝对源码导入" tone="warning">
不要写 <code>import Button from "C:\\Users\\...\\crab-dev\\components\\rc-button"</code>。绝对路径只在一台电脑有效，还会绕过 npm exports、声明文件和依赖完整性验证。
</Callout>

## 排错

### 无法解析 @linaria/core

执行当前章节的安装命令，并确认它出现在项目根 dependencies。不要在 Wake resolver 中添加包名特例。

### 组件没有样式

确认从 `@crab-dev/rc-*` 包根导入，并确认已发布包包含 `css/index.css`。Wake 会自动把它加入生产输出，不要复制 node_modules 内的 hash class，也不要在业务文件中重复导入同一份 CSS。

### 暗色主题出现白色卡片

补齐 background、text、border 的语义变量映射。组件 fallback 主要面向默认亮色。

### TypeScript 找不到声明

确认从包根导入，不要绕到 `esm/index.mjs`；package root exports 会同时提供 types 条件。

### React 出现重复实例

确认组件库把 React 作为 peer，当前项目只安装一套 React 19，并避免从另一个本机 workspace 绝对导入源码。

## 升级检查清单

将升级验收拆成三个阶段。任一项未通过都不要发布：先确保依赖和构建稳定，再做页面回归。

### 依赖与版本

- [ ] 已确认目标 npm 包版本
- [ ] `package.json` 与锁文件内容一致
- [ ] 项目满足 React 19 peer dependency 要求
- [ ] 组件所需的运行时依赖均已安装

### 构建与解析

- [ ] ESM 入口和 CSS 子路径均可解析
- [ ] `wake docs build` 构建成功

### 站点回归

- [ ] 首页、提示块和组件示例显示正常
- [ ] `light`、`dark`、`system` 三种主题均正常
- [ ] 移动端页面没有横向滚动
- [ ] 文档中的版本号和临时解决方案已同步更新

完成首次接入后，可以进入[Demo 与 Props API](../docs/demo-api)学习如何把真实 npm 组件编排成教学示例；升级失败时直接按[故障排查](../reference/troubleshooting)的模块解析、样式和 React 章节定位。
