# CLI 参考

Wake 使用子命令。先选择要做的事情，再填写项目根、入口或输出选项。

## 查看帮助和版本

```bash
wake --help
wake --version
wake build --help
wake docs build --help
```

当文档示例与本机行为不一致时，以当前二进制的 `--help` 为准，并确认没有运行到 PATH 中的旧版本。

## 全局语法

```text
wake [--no-color] <COMMAND>
```

| 选项 | 说明 |
| --- | --- |
| `--no-color` | 强制关闭 ANSI 彩色输出 |
| `--help` | 显示当前层级帮助 |
| `--version` | 显示 Wake 版本 |

Wake 同时遵循 `NO_COLOR` 环境变量。CI 日志无法正确显示颜色时使用全局选项：

```bash
wake --no-color docs build .
```

全局选项放在子命令之前最清楚。

## wake build

```text
wake build [ENTRY] [--outdir dist] [--cache] [--watch] [--sourcemap]
```

### 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `ENTRY` | 配置或 `src/entry.tsx` | 可选入口文件 |
| `--outdir` | `dist` | 输出目录 |
| `--cache` | 关闭 | 使用 `.wake/cache.bin` |
| `--watch` | 关闭 | 完成后继续监听生产重建 |
| `--sourcemap` | 关闭 | 输出精确 Source Map，并关闭压缩和分割 |

### 常用组合

```bash title="标准生产构建"
wake build --outdir dist
```

```bash title="指定入口"
wake build src/admin.tsx --outdir dist-admin
```

```bash title="跨进程缓存"
wake build --cache --outdir dist
```

```bash title="持续观察 production"
wake build --watch --outdir dist
```

```bash title="调试模块位置"
wake build --sourcemap --outdir dist-debug
```

`ENTRY` 是位置参数，不要写成 `--entry`；`--entry` 只属于 `wake dev`。

## wake dev

```text
wake dev [ROOT] [--entry FILE] [--port 5173]
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `ROOT` | `.` | 项目根发现起点 |
| `--entry` | 配置入口 | 临时覆盖 `[html].entry` |
| `--port` | `5173` | 监听端口 |

例子：

```bash
wake dev .
wake dev packages/admin --port 5174
wake dev . --entry src/playground.tsx --port 5175
```

普通 dev 的端口参数有 CLI 默认值，因此想使用非 5173 时应显式传入。

## wake docs dev

```text
wake docs dev [ROOT] [--port 5173]
```

例子：

```bash
wake docs dev .
wake docs dev packages/ui
wake docs dev . --port 5174
```

该命令会：

- 扫描 MDX 和 Demo；
- 提取 API；
- 生成路由、侧栏和搜索索引；
- 启动开发服务器；
- 在文件新增、修改、删除时增量再生成。

端口优先级是命令行、`[dev_server].port`、5173。

## wake docs build

```text
wake docs build [ROOT] [--outdir docs-dist] [--base /path/]
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `ROOT` | `.` | 文档项目根 |
| `--outdir` | `docs-dist` | 静态输出目录 |
| `--base` | `[docs].base_path` | 临时覆盖部署路径 |

例子：

```bash
wake docs build .
wake docs build packages/ui --outdir site
wake docs build . --base /design-system/ --outdir docs-dist
```

相对 outdir 以解析后的项目根为基准。生产模式排除 draft 页面。

## wake parse

```text
wake parse FILE [--ast]
```

解析 JavaScript、TypeScript、JSX 或 TSX 文件。默认输出解析结果摘要；`--ast` 输出 JSON AST：

```bash
wake parse src/entry.tsx
wake parse src/entry.tsx --ast
```

它用于调查语法解析，不会执行完整项目构建。`.cjs` 按脚本解析，其他常见源文件按模块解析。

AST 输出可能很长，PowerShell 可以保存：

```powershell
wake parse src/entry.tsx --ast |
  Set-Content -Encoding utf8 ast.json
```

## wake tokenize

```text
wake tokenize FILE
```

输出词法 token 流：

```bash
wake tokenize src/entry.tsx
```

它适合定位字符串、模板、正则、JSX 边界等词法问题。普通应用开发不需要日常使用。

## 项目脚本

把稳定命令写入 `package.json`：

```json title="package.json"
{
  "scripts": {
    "dev": "wake dev .",
    "build": "wake build --outdir dist",
    "docs:dev": "wake docs dev .",
    "docs:build": "wake docs build . --outdir docs-dist"
  }
}
```

团队成员随后使用：

```bash
npm run dev
npm run docs:dev
npm run docs:build
```

优点是命令、根目录和输出目录在仓库中可见，不依赖口头约定。

## 从 Wake 源码仓库运行

尚未把二进制加入 PATH 时，可以在 Wake 仓库执行：

```bash
cargo run -q -p wake_cli -- docs build .
```

注意最后的 `.` 此时会指向 Wake 仓库本身。要构建其他项目，应传目标项目路径：

```powershell
cargo run -q -p wake_cli -- docs build C:\projects\my-ui
```

正式团队项目更推荐构建 release 二进制并以固定方式提供给 CI。

## 参数排错

### unexpected argument

运行当前子命令的 `--help`。常见原因是把 `wake build` 的位置入口写成 `--entry`，或把 docs 的 `--base` 写到普通 build。

### 找错项目根

显式传 ROOT：

```bash
wake docs dev ./packages/ui
```

再检查该目录或父目录的 `wake.config.toml` 和 `package.json`。

### 输出到了意外目录

普通 build 的 outdir 按当前命令行为解析；docs build 的相对 outdir 以项目根解析。使用绝对路径前先确认目标，避免指向源码目录。

## 退出状态

| 状态 | 含义 |
| --- | --- |
| `0` | 命令成功 |
| 非零 | 配置、解析、生成、构建、服务启动或写盘失败 |

CI 必须让非零状态中止发布，不要在命令后无条件忽略错误。

Wake 诊断通常包含：

- 错误代码；
- 文件路径；
- 行和列；
- 源码上下文；
- 具体依赖或属性名。

排错时先处理第一条根因，再重新执行命令。
