# docs 命令

首次使用请先阅读[建立文档站](/wake-docs/create-site)。

启动、页面按需编译或构建卡顿时，在命令后加 `--progress`，例如 `wake docs dev --progress`。
详见[定位构建卡顿](/reference/cli/build#定位构建卡顿)，可查看 Docs 准备和原生构建的活动步骤。

## 开发

```text
wake docs dev [ROOT] [--port PORT] [--mode site|components]
```

## 构建

```text
wake docs build [ROOT] [--outdir DIR] [--base PATH] [--mode site|components]
```

`--base` 临时覆盖 `[docs].base_path`。`site` 构建 MDX 文档站；`components` 启动或构建 Demo 工作台，不扫描 MDX 页面。

构建命令会验证导航、页面、Demo 和 API，然后为每个公开路由生成 HTML shell。输出目录默认来自 Wake Docs 配置或 `docs-dist`。
单站和聚合构建都先在同盘 staging 中生成 bundle、路由 shell 与 public 资源，全部成功后再提交。
输出目录必须是新的、空的，或带有 Docs 产品 `.wake-output.json` 标记；Wake 不会清理非空的
未标记目录，也不会通过符号链接或 Windows reparse point 发布。

当站点配置了 `[[docs.workspace]]` 时，默认 `site` 命令会聚合全部匹配工作区。生产构建
总是构建全部工作台，并在全部成功后事务式发布；开发服务器在同一端口按挂载路径提供
站点和工作台，`lazy` 工作区直到第一次请求才打包。显式 `--mode components` 仍只运行当前
项目的 standalone 工作台，不执行聚合发现。

## Demo 视觉回归（experimental）

```text
wake docs test [ROOT] [--theme light|dark ...] [--viewport WIDTHxHEIGHT ...]
               [--update-snapshots] [--browser-path FILE] [--headful]
               [--reporter pretty|json|junit] [--output FILE]
```

自动发现当前单站文档目录中的 Demo，构建真实生产页面，再按主题与视口组合截图。默认矩阵为
light/dark × 1280×720/390×844；重复 `--theme` 或 `--viewport` 可以覆盖对应轴。每个组合使用独立
浏览器上下文，保留 Docs Preview、CSS、资源和 Demo 的初始 `meta.args`。

首次运行缺失基线会失败；审核后显式加 `--update-snapshots` 创建或更新，再移除该参数运行 CI。
基线沿用 Wake Test 的渲染 profile，保存在每个 Demo 旁的 `__screenshots__`；失败比较生成
`__diffs__` 中的 received PNG 和 HTML 差异页面。报告中的 suite 路径与名称定位 Demo、主题和视口。
不会把加载占位、渲染错误、资源失败或超时保存成成功基线。

```bash
npx wake docs test . --update-snapshots
npx wake docs test . --reporter json --output reports/demos.json
```

首版只验证单站 Demo 的初始渲染；工作区聚合配置会明确拒绝，请分别指定子项目根目录。
需要系统 Chrome、Edge 或 Chromium；外部网络不开放，Demo 应使用本地确定性资源。
浏览器 locale、timezone、sandbox、设备比例和超时沿用 `[test]` 配置；主题与视口由本命令矩阵指定。
退出码沿用测试命令：成功 0、测试失败 1、配置/构建/宿主错误 2、取消 130。

## 开发控制台

交互式终端中的 `docs dev` 默认启用全屏控制台，也可以用 `--ui plain` 强制输出流式日志。控制台的
`Activity`、`Recent Problems` 和 `Changes` 视图分别展示事件时间线、带源码位置的近期诊断，以及
按 workspace/base path 归属的重建批次。失败的聚合工作区会直接列出名称。

使用 `Tab` / `Shift+Tab` 切换视图，`PageUp` / `PageDown` 滚动，`Ctrl+End` 返回最新事件。
`Recent Problems` 是有界的进程内历史，不表示问题当前仍未解决；输入 `clear` 会清空三个视图，
但不会清除本地地址、最新构建指标或工作区加载状态。
