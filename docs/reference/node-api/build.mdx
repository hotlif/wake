# Node.js 构建 API

```ts
import { build, buildLibrary, bundle, createBuildContext, generateCssToken, generateDocgen } from "@crab-dev/wake";
```

## `build(options)`

写入生产文件并返回模块数、缓存命中、耗时、诊断和输出文件清单。

```ts
const result = await build({ cwd: process.cwd(), outdir: "dist", cache: true });
console.log(result.files);
```

启用 `cache` 时，持久层只保存由真实源码内容派生的摘要和生成结果，不保存源码或文件时间戳。
缓存损坏、I/O 或并发提交问题不会拒绝 Promise，而是在成功结果的 `diagnostics` 中返回最多一条
`code: "WAKE_CACHE"` warning；缺失和 schema 不兼容保持静默。

`outdir` 必须是新目录、空目录，或带有匹配 `.wake-output.json` 的 Wake 应用输出目录。项目根、
项目祖先、包含入口的目录、符号链接和 Windows reparse point 会以 `WAKE_CONFIG` 拒绝。非空的
未标记旧目录不会被自动接管；升级时请先确认并删除旧产物，或改用新的空目录。应用、Federation、
HTML 与 manifest 在同盘 staging 中全部成功后才提交，失败会保留上一份有效输出。

浏览器应用可通过 `federation` 覆盖或提供同构的 Wake-native Federation 配置。Node API 使用
camelCase 字段；`enabled: true` 时 `name` 必填：

```ts
const react18 = {
  scope: "react18",
  requiredVersion: "^18.3.0",
  singleton: true,
  strict: true,
  coherenceGroup: "react18",
  owner: "shell",
} as const;

await build({
  cwd: process.cwd(),
  federation: {
    enabled: true,
    name: "shell",
    remotes: {
      catalog: {
        manifestUrl: "https://catalog.example.com/wake-federation.json",
        allowedOrigins: ["https://catalog.example.com"],
        devFollow: false,
      },
    },
    exposes: {
      "./Button": {
        entry: "src/button.tsx",
        mode: "host-rendered",
        scope: "react18",
        shadow: "none",
        allowGlobalCss: false,
      },
    },
    shared: {
      react: react18,
      "react/jsx-runtime": react18,
      "react/jsx-dev-runtime": react18,
      "react-dom": react18,
      "react-dom/client": react18,
    },
  },
});
```

该选项只支持 browser/Wake-native 构建；remote 通过字面量动态 `import("catalog/Button")`
加载，不提供 Webpack/Rspack ABI、静态远程导入或 Node/SSR federation。
`host-rendered` expose 必须在同一 scope 完整声明 React、两个 JSX runtime、React DOM 及
`react-dom/client`，五项使用同一个 singleton coherence group 与一致的 owner。它默认只允许
CSS Modules 与 Wake CSS-in-JS；同步或异步 closure 中的普通 `.css` 会使构建以
`FED_CONFIG_INVALID` 失败。只有明确接受样式进入宿主 document 时才设置
`allowGlobalCss: true`；该字段不写入 Federation Manifest。

## `bundle(options?)`

返回独立的 `BundleResult`，其中 `code` 始终存在。省略 `outfile` 时只在内存中返回；设置后
原子写入该文件且不生成 HTML、manifest 或其他 Web 应用产物。`platform: "node"` 会默认
选择 `format: "cjs"` 和 `target: "node20"`，这些默认值由 Wake 应用层统一决定。

Node/CommonJS bundle 可指定宿主 external：

```ts
const result = await bundle({
  entry: "src/extension.ts",
  outfile: "dist/extension.js",
  platform: "node",
  format: "cjs",
  target: "node20",
  external: ["vscode"],
  minify: true,
  sourceMap: true,
});
console.log(result.outputFile);
```

Node 平台自动外置 Node 内置模块。显式 external 必须是裸 npm 包名并同时覆盖其子路径。
首版 Node bundle 只支持 CommonJS 单文件，`minify` 与 `sourceMap` 可以同时启用；生成 map 不会
选择另一套未压缩代码，也不改变 JavaScript 主体。
`minify` 使用 Wake 集中式的 Closure 风格有序 pass/固定点管线；这不是 Closure `ADVANCED`
兼容模式，Node API 不新增 externs 或 whole-world 选项。
启用 `sourceMap` 时，内存构建通过 `result.sourceMap` 返回映射；设置 `outfile` 后还会原子写入
`<outfile>.map`、返回 `result.sourceMapFile`，并在 JavaScript 末尾写入对应的
`sourceMappingURL`。JavaScript 与 map 属于同一次集合事务；任一安装失败都会恢复旧集合。
`outfile` 或 map 与本轮实际读取的入口、传递依赖、配置、package/PnP 文件或其物理 alias 重合时，
Promise 以 `WAKE_OUTPUT_COLLISION` 拒绝。`sourceMap: false` 不会删除无法证明归属的相邻旧 map。

## `buildLibrary(options)`

构建组件发布合同：真实 ESM、CommonJS、声明入口和可选静态 CSS。所有裸包保持 external，四个
输出目录使用 staging 与备份交换统一提交。公开类型无法安全生成或静态 CSS 无法证明时 Promise
会拒绝，上一份有效产物保持不变。

```ts
const result = await buildLibrary({ cwd: "components/rc-button", entry: "src/index.ts" });
console.log(result.esmEntry, result.cjsEntry, result.declarationEntry, result.cssEntry);
```

## `generateCssToken(options)`

原生解析组件包的 `token.toml`，并把 TypeScript 写到 `[build].output`。`configPath`
相对 `cwd` 解析，默认是 `token.toml`。递归导入支持 Yarn PnP 与传统 `node_modules`；
循环、缺失 `$ref`、非法配置和写盘失败都会拒绝 Promise，已有输出不会被半成品覆盖。输出若与
根/递归 token 配置、resolver 读取的 package/PnP 元数据或 archive 是同一文件或 alias，则以
`WAKE_OUTPUT_COLLISION` 拒绝且输入字节不变。

```ts
const result = await generateCssToken({
  cwd: "components/rc-button",
  configPath: "token.toml",
  signal: AbortSignal.timeout(10_000),
});

console.log(result.outputFile);
```

## `generateDocgen(options)`

使用与 `wake library docgen` 相同的 Rust 后端生成 `public/docgen.json`。`entry` 相对 `cwd`
解析；省略时先读取 `package.json.docgen.entry`，再追踪 `src/index.ts` 的默认导出。解析、
公开 props 类型推断或写盘失败都会拒绝 Promise，且不会覆盖上一份有效输出。入口解析和递归类型
解析会返回实际读取 provenance；`public/docgen.json` 与任一输入或物理 alias 重合时以
`WAKE_OUTPUT_COLLISION` 拒绝。

```ts
const result = await generateDocgen({
  cwd: "components/rc-button",
  entry: "src/button.tsx",
  signal: AbortSignal.timeout(10_000),
});

console.log(result.outputFile);
```

## `createBuildContext(options)`

返回可重复 `rebuild()` 的 `BuildContext`。结束时必须 `close()`，也可使用 `await using` 调用异步释放。

所有操作都接受 `AbortSignal`。失败抛出 `WakeError`，调用方应根据 `code` 分支并展示 `diagnostics`。
诊断继续提供 `path`、`start`、`end` 字节范围；存在有效源码 span 时还提供 `location`：

```ts
interface DiagnosticLocation {
  line: number;       // 1 基
  column: number;     // 1 基
  endLine: number;    // 1 基，结束位置排他
  endColumn: number;
  lineText: string;
  label?: string;
}
```

开发服务器的 `diagnostic` 事件传入同一个结构化 `Diagnostic`，不会把整次构建失败压成一段文本。
