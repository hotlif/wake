# Node.js API

`@crab-dev/wake` 提供与 CLI 共用实现的 Node.js API。包同时支持 ESM、CommonJS 和 TypeScript，运行时要求 Node.js `>=22.14 <27`。

```bash
npm install --save-dev @crab-dev/wake
```

## 导入

```js title="ESM"
import {
  WakeError,
  build,
  buildDocs,
  bundle,
  createBuildContext,
  startDevServer,
  startDocsDevServer,
  version,
} from "@crab-dev/wake";
```

```js title="CommonJS"
const {
  WakeError,
  build,
  startDevServer,
} = require("@crab-dev/wake");
```

包也提供包含同一组成员的默认导出。团队代码建议使用具名导入，便于类型检查和按名称搜索。

## 通用项目选项

构建、上下文和服务器 API 都接受以下项目选项：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `cwd` | `string` | 项目根发现起点；省略时使用当前工作目录 |
| `configPath` | `string` | 显式配置文件；必须存在且指向文件 |
| `signal` | `AbortSignal` | 取消启动或构建操作 |

`configPath` 用于选择配置文件，不改变配置内相对路径的解析规则。无效目录、缺失配置或非法 TOML 会抛出 `WAKE_CONFIG`。

## version

```ts
function version(): string
```

返回原生 Wake 版本，可用于诊断主包与平台包是否一致。

## build

```ts
function build(options?: BuildOptions): Promise<BuildResult>
```

执行一次生产构建并写入输出目录。

```js
const result = await build({
  cwd: process.cwd(),
  entry: "src/entry.tsx",
  outdir: "dist",
  cache: true,
  sourceMap: false,
});

console.log(result.moduleCount, result.files);
```

| 选项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `entry` | `string` | 配置或 `src/entry.tsx` | 临时覆盖入口 |
| `outdir` | `string` | `dist` | 写盘目录 |
| `cache` | `boolean` | `false` | 使用跨进程持久化缓存 |
| `sourceMap` | `boolean` | `false` | 输出 Source Map，并关闭压缩与代码分割 |

`BuildResult` 包含模块、缓存、耗时、输出目录、文件清单和诊断：

```ts
interface BuildResult {
  success: true;
  moduleCount: number;
  updatedModuleCount: number;
  cachedModuleCount: number;
  durationMs: number;
  outputDir?: string;
  code?: string;
  files: Array<{
    path: string;
    kind: "chunk" | "css" | "asset" | "html";
    bytes: number;
  }>;
  diagnostics: Diagnostic[];
}
```

构建失败时 Promise 会 reject，不会返回 `success: false`。

## bundle

```ts
function bundle(options: BuildOptions): Promise<BundleResult>
```

执行内存构建，不写 `outdir`。返回值继承 `BuildResult`，其中 `code` 始终为字符串，`outputDir` 始终为 `undefined`。

```js
const result = await bundle({ cwd: process.cwd(), entry: "src/worker.ts" });
console.log(result.code);
```

需要 HTML、CSS、独立资源或多个 chunk 时使用 `build()`；`bundle()` 适合读取单一 JavaScript 结果的工具集成。

## createBuildContext

```ts
function createBuildContext(options?: BuildOptions): Promise<BuildContext>
```

创建持有增量状态的长生命周期构建上下文。首次和后续构建都通过 `rebuild()` 触发：

```js
await using context = await createBuildContext({
  cwd: process.cwd(),
  outdir: "dist",
});

const initial = await context.rebuild();
const updated = await context.rebuild(["src/button.tsx"]);
```

```ts
class BuildContext {
  readonly closed: boolean;
  rebuild(changedPaths?: string[], options?: { signal?: AbortSignal }): Promise<BuildResult>;
  rebuild(options?: { signal?: AbortSignal }): Promise<BuildResult>;
  close(): Promise<void>;
  [Symbol.asyncDispose](): Promise<void>;
}
```

`changedPaths` 应传项目中实际发生变化的路径；省略时执行正常重建。`close()` 可重复调用。关闭后再 `rebuild()` 会抛出 `WAKE_INTERNAL`。

不使用 `await using` 时必须在 `finally` 中关闭：

```js
const context = await createBuildContext({ cwd: process.cwd() });
try {
  await context.rebuild();
} finally {
  await context.close();
}
```

## startDevServer

```ts
function startDevServer(options?: DevServerOptions): Promise<DevServer>
```

启动应用开发服务器和 HMR：

```js
const server = await startDevServer({
  cwd: process.cwd(),
  host: "127.0.0.1",
  port: 5173,
  open: false,
});

console.log(server.url);
await server.waitUntilClosed();
```

`DevServerOptions` 在通用项目选项上增加 `entry`、`host`、`port` 和 `open`。返回的服务器是 `EventEmitter`：

```ts
server.on("rebuildStart", ({ changedPaths }) => {});
server.on("rebuilt", (event) => {});
server.on("diagnostic", (diagnostic) => {});
server.on("closed", () => {});
```

`rebuilt` 事件包含 `initial`、模块/chunk/资源数量、更新与缓存模块数及 `durationMs`。`diagnostic` 事件用于报告服务运行期间的构建错误。

```ts
class DevServer extends EventEmitter {
  readonly url: string;
  close(): Promise<void>;
  waitUntilClosed(): Promise<void>;
  unref(): this;
  [Symbol.asyncDispose](): Promise<void>;
}
```

- `close()` 请求关闭并等待资源释放，可重复调用；
- `waitUntilClosed()` 适合 CLI 或常驻进程；
- `unref()` 允许没有其他活动句柄时 Node.js 自然退出；
- `[Symbol.asyncDispose]()` 支持 `await using`。

## buildDocs

```ts
function buildDocs(options?: DocsBuildOptions): Promise<DocsBuildResult>
```

构建静态文档站或组件工作台：

```js
const result = await buildDocs({
  cwd: process.cwd(),
  outdir: "docs-dist",
  basePath: "/design-system/",
  mode: "site",
});
```

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `outdir` | `string` | `docs-dist` | 静态输出目录 |
| `basePath` | `string` | `[docs].base_path` | 临时覆盖部署路径 |
| `mode` | `"site" \| "components"` | `"site"` | 完整文档站或组件工作台 |

返回值除普通构建指标外，还包含 `mode`、`routes` 和 `demos`。Components 模式不要求 MDX，`routes` 可以为空；Demo 记录包含分组、组件、排序、Controls 数量和警告。

## startDocsDevServer

```ts
function startDocsDevServer(options?: DocsDevServerOptions): Promise<DevServer>
```

启动文档开发服务器。选项与 `startDevServer()` 相同，并增加 `mode`：

```js
await using server = await startDocsDevServer({
  cwd: process.cwd(),
  mode: "components",
  port: 5174,
});

console.log(server.url);
await server.waitUntilClosed();
```

返回值、事件和关闭语义与应用 `DevServer` 完全一致。

## 取消

一次性 API 和服务器启动都支持 `AbortSignal`：

```js
const controller = new AbortController();
const pending = build({ cwd: process.cwd(), signal: controller.signal });
controller.abort();

await pending.catch((error) => {
  if (error instanceof WakeError && error.code === "WAKE_CANCELLED") return;
  throw error;
});
```

`BuildContext.rebuild()` 的 signal 放在第二个选项参数中。取消是协作式的；收到结果或错误后才表示本次操作已经结束。

## WakeError 与诊断

所有公开异步 API 使用 `WakeError` 报告稳定的顶层错误类别：

| 错误码 | 含义 |
| --- | --- |
| `WAKE_CONFIG` | 根目录、配置文件或配置值无效 |
| `WAKE_PARSE` | 独立解析操作失败 |
| `WAKE_BUILD` | 应用或文档构建失败 |
| `WAKE_IO` | 文件、目录、端口或服务器 I/O 失败 |
| `WAKE_CANCELLED` | 操作被 AbortSignal 取消 |
| `WAKE_UNSUPPORTED_PLATFORM` | 当前平台没有可用原生包 |
| `WAKE_INTERNAL` | 资源已关闭、原生任务 panic 或内部不变量失败 |

```js
try {
  await build({ cwd: process.cwd() });
} catch (error) {
  if (!(error instanceof WakeError)) throw error;
  console.error(error.code, error.path, error.message);
  for (const diagnostic of error.diagnostics ?? []) {
    console.error(diagnostic.severity, diagnostic.code, diagnostic.message);
  }
}
```

`Diagnostic` 可包含路径、字节区间和补充说明。不要根据英文错误文本分支；使用 `code`，并把诊断展示给用户。
