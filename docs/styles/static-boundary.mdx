# 理解静态求值边界

css 模板中的值需要在构建时确定。固定间距直接写在模板中；由 props 或用户操作决定的值，通过 CSS 变量传入。

## 可以求值

构建期样式要求值可以在不执行业务副作用的前提下确定。常见支持项包括字面量、模板、数字运算、字符串拼接、模块顶层不可变常量，以及经 ESM 传递的叶子字符串和数字。

```tsx title="src/StaticCard.tsx"
import { css } from "@crab-dev/css";
const unit = 4;
const gap = `${unit * 2}px`;
const box = css`padding: ${gap};`;
export function StaticCard() { return <div className={box}>固定间距</div>; }
```

## 会被拒绝

用户函数调用、getter、可变对象和逃逸引用，以及 window、process、网络、文件系统和随机值，不能作为任意可执行插值。相对 `url()` 也需要移到普通 CSS 资源管线。无法确定值时，构建会指出具体表达式；按下面的表格选择调整方式。

## 解决方法

| 不能静态确定的来源 | 调整方式 |
| --- | --- |
| React props 或状态 | 用 createVar/assignVars 写运行时值 |
| 固定设计常量 | 提取为清楚的不可变叶子常量 |
| 主题选择 | 分配 CSS 自定义属性，模板保持静态 |
| 相对图片、字体 | 使用普通 CSS url 或资源 import |
| 第三方函数计算 | 在可控构建前置步骤生成固定值，或在运行时传变量 |

## 错误码

`CRAB_CSS_STATIC_VALUE` 表示值无法安全求出；`CRAB_CSS_RELATIVE_URL` 指向资源路径限制；`ERR_WAKE_CSS_NOT_COMPILED` 表示样式 API 没有经过要求的编译路径。从诊断指出的表达式开始检查。修改 TypeScript 类型不会使运行时值变成构建时常量。

## 验证方式

先构建上面的常量示例，再将 gap 改成读取运行时状态，确认诊断清楚。按动态变量教程调整后再次构建，检查 CSS 中保留变量引用、DOM 上有实际赋值。
