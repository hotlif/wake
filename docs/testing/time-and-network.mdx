# 控制时间与网络

让测试主动推进时间、提供请求结果，可以快速且重复地检查加载、成功和失败状态。

## 控制时间

```ts title="src/timer.test.ts"
import { clock, expect, test } from "@crab-dev/wake/test";

test("到达延时后执行", async () => {
  await clock.fake();
  try {
    let ready = false;
    setTimeout(() => { ready = true; }, 1000);
    await clock.advanceBy(999);
    expect(ready).toBe(false);
    await clock.advanceBy(1);
    expect(ready).toBe(true);
  } finally {
    await clock.restore();
  }
});
```

时钟操作是异步的，需要 await。逐步推进能证明边界时刻，不需要真的等待一秒。不要对永远重复的 interval 无限制调用 `runAll`，应推进有限时间并清理任务。

## 路由接口请求

```ts title="src/network.test.ts"
import { expect, network, test } from "@crab-dev/wake/test";

test("读取接口结果", async () => {
  const dispose = network.route("https://example.test/user", () => ({
    status: 200,
    headers: { "content-type": "application/json" },
    body: JSON.stringify({ name: "Ada" }),
  }));
  try {
    const response = await fetch("https://example.test/user");
    expect(await response.json()).toEqual({ name: "Ada" });
  } finally {
    dispose();
  }
});
```

此测试不访问外部站点。默认网络策略拒绝未允许的真实请求；请求路由提供受控响应。需要真实集成测试时，通过项目 `allow_hosts` 或 `network.allow` 显式允许目标，并单独管理服务可用性。

## 检查失败路径

把响应改成错误状态或延迟，验证应用显示错误或加载状态，而不是只测试成功 JSON。测试结束后路由和记录会清理；对本测试手动创建的资源仍可显式释放，便于理解生命周期。

## 验证方式

分别执行两个文件，确认计时测试无需实际等待、请求测试无需公网。未命中的网络请求应给出网络诊断，不应默默访问未知服务。
