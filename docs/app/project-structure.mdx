# 项目结构与最小配置

应用入口只负责启动页面，组件单独导出。这样，同一个组件可以用于应用、测试和文档示例。

## 推荐结构

沿用[快速开始](/start/create-react-app)，把可独立测试的组件从入口拆出：

```text
my-app/
  package.json
  wake.config.toml
  tsconfig.json
  public/
    robots.txt
  src/
    entry.tsx
    Counter.tsx
    Counter.test.tsx
    style.css
```

`entry.tsx` 负责找到 HTML 容器并挂载应用；`Counter.tsx` 只导出组件。测试导入组件即可，不必触发整页挂载。`public` 存放固定 URL 的公开文件，组件专属图片可以和组件放在一起并通过 import 引用。

## 入口原则

```tsx title="src/Counter.tsx"
import { useState } from "react";

export function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(value => value + 1)}>点击次数：{count}</button>;
}
```

在入口中导入 `Counter` 并渲染。组件模块不调用 `createRoot`，使它可以同时被应用、测试和文档 Demo 使用。配置中的相对路径以有效项目根为基准；使用 `root_dir` 调整根时，所有相关路径都需要一起核对。

## 源码和产物

`dist` 是应用输出，`.wake` 是 Wake 的生成或缓存目录。不要手改这些目录来修复源码问题，也不要从中导入业务模块。它们的内容应当能由源码和配置重新生成。

提交源码、配置和依赖锁文件。通常忽略 `dist/`、`.wake/`、`node_modules/`；测试快照是否提交取决于它是不是需要审核的预期基线。库构建和文档构建有独立产物，见对应教程。

## 验证方式

从项目根执行类型检查和构建。确认删除入口之外的演示文件不会改变应用；改变实际导入的组件会触发更新。若从子目录运行命令，检查终端识别的配置和根目录是否符合预期。
