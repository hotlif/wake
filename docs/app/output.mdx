# 理解构建产物

构建成功后，通常只需发布完整的输出目录。下面说明各类文件的用途，以及哪些开发文件不需要上传。

## 一份产物的组成

| 文件类型 | 用途 | 使用方式 |
| --- | --- | --- |
| HTML | 引用本次构建入口 | 由静态服务器返回 |
| JavaScript | 应用入口与按需加载模块 | 由 HTML 和模块引用 |
| CSS | 普通 CSS 与提取样式 | 与当前 JavaScript 一起发布 |
| 图片、字体等资源 | 被源码使用的资源 | 使用构建重写后的 URL |
| `manifest.json` | 描述逻辑入口与实际产物关系 | 供需要集成资源清单的工具读取 |
| Source Map | 把错误映射回源码 | 按团队调试策略保存或部署 |
| `.wake-output.json` | 输出目录所有权标记 | 由 Wake 维护 |

不要依赖固定哈希或 chunk 数量。入口相同但依赖图变化时，分块结果也可能变化。无需后端集成的静态应用通常只需发布完整目录，不必自行解析 manifest。

## 和源码目录的区别

应用输出不包含完整开发依赖安装树。第三方包是否进入产物由构建路径和引用决定；组件库则有不同的 external 规则，见[库构建](/app/library)。`.wake` 中的缓存与生成中间文件不是静态站点发布内容。

## 检查产物

连续构建相同源码，检查入口能够加载全部引用。改变一个资源后重新构建，检查页面引用随之更新。对比文件大小时使用同一依赖锁文件、浏览器目标和构建选项；不要把 Source Map 的体积误算成首屏下载体积。
