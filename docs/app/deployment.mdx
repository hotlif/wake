## 构建可发布目录

```bash
npm ci
npm run typecheck
npm run build
```

需要子路径时，在项目配置顶层设置 `public_path = "/portal/"`，然后重新构建。不要只在上传完成后挪动目录而不检查构建引用。应用路由库的 base 与手写资源 URL 也需要匹配。

## 配置静态托管

静态服务器的公开目录指向完整构建产物。根部署时首页位于 `/`；子路径部署时产物需映射到 `/portal/`。应用使用 history 路由时，未命中真实静态文件的应用页面请求回退到对应 index.html；API 请求和丢失的资源不能无差别返回 HTML。

| 内容 | 建议处理 |
| --- | --- |
| HTML | 短缓存或重新验证 |
| 内容哈希资源 | 长缓存，可使用 immutable |
| 固定名称公开文件 | 根据更新要求设置缓存 |
| `/api` 请求 | 交给生产网关，不依赖开发代理 |

新 HTML 与它引用的全部资源应来自同一份构建。保留完整上一版发布集合便于回退，不只备份 HTML。

## 验证方式

依次检查首页、直接输入子路由、刷新、前进后退、动态导入、图片字体和 API。Network 面板中 JavaScript 请求不能返回 HTML。更新一处内容重新构建后，确认页面使用新版本资源，旧版本回退也能完整加载。

## 常见错误

- 客户端跳转成功，刷新 404：补充对应挂载路径的应用路由回退。
- JS 报意外的 `<`：静态资源缺失却被回退成 HTML，检查公开路径。
- 生产 API 失败：开发 proxy 不会随 dist 发布，需要生产转发。
