# ADR 0064: 原生 lint 类型服务

- Status: proposed
- Date: 2026-09-14

## Context

十条类型规则需要跨文件的流类型、签名、可赋值性和字面量联合；名称或文本匹配不能提供这些
事实。P0 实验已经验证 TypeScript 7.0.2 原生服务的多项目、未保存依赖与旧快照隔离。
进一步实验通过其原生 stdio JSON-RPC 直接查询节点类型，证明不需要 JavaScript 规则宿主。
该服务是不稳定版本协议，不能向 Wake 公共 SDK 暴露它的节点或内部类型句柄。

## Decision

候选类型后端固定为安装在用户项目中的 TypeScript 7.0.2 原生可执行文件。应用层通过统一
ResolutionEnvironment 定位声明的 compiler package 和匹配平台包；不下载依赖，不按 PATH
碰运气寻找不同版本，不执行 JavaScript 配置。未启用类型规则时不启动类型进程。
编译器设置为包名（允许 npm alias），默认 `typescript`，必须在 lint 项目最近的 package.json
中声明。编译器实体须为 `typescript@7.0.2`，其对应平台的 optionalDependency 及平台包
实体版本也须为 `7.0.2`。首轮支持 Windows/macOS/Linux 的 x64、arm64 定位；不支持的平台、
缺包、版本不符及 archive 内无法直接启动的可执行文件均明确失败。平台包从编译器 issuer
及其 PnP 上下文解析，不能从项目根碰巧找到的另一安装位置代替。单份 manifest 至多 1 MiB。

应用拥有每轮类型会话、配置/未保存源码、冻结文件系统、项目选择和取消。以 stdio
JSON-RPC 连接原生 `--api --async` 服务；所有只读文件系统回调经应用的快照及 resolver-owned
PnP 视图完成，不能让后端绕过未保存源码或读到另一份安装图。协议 envelope 拒绝重复或未知
字段，显式 null 结果仍与缺失结果区分。类型解析使用实际 tsconfig
的 TypeScript 条件与路径规则；模块规则继续使用 ADR 0063 的 Wake 模块解析策略，两者的
差异须向用户解释，不能伪造相同的解析结果。
原生 TypeScript 的文件查询使用 resolver-owned 只读 `node_modules` 投影视图：受 PnP 管理的
虚拟目录只暴露对应 issuer 可以解析的声明/fallback 依赖，裸包 alias、scoped 包、未满足 peer
与嵌套 PnP 根保持既有权威。物理 `node_modules` 不能填补 PnP 拒绝。传递虚拟查询携带原
PnP 上下文，文件内容经现有 PnP/ZIP 文件系统读取；投影身份保留导入上下文，watch 跟踪实际
物理输入。普通/被 PnP 忽略的路径仍使用经典文件系统，不增加第二个包求解器。
查询视图属于所选项目的解析上下文。原生解析器爬升到该 dependency tree 所有包之外的公共
祖先时，该祖先的 `node_modules` 不能恢复已被 PnP 拒绝的依赖；非祖先的普通目录仍使用
经典布局，实际最近 PnP 根及其 ignored 规则继续优先。
当依赖位于原 PnP 根外，类型会话用私有、临时的逻辑路径保留解析上下文；该映射保留整个
物理卷的相对关系，不能把 `../` 导入改作项目根的另一个包。不同权威映射到不同逻辑命名
空间，最近物理 PnP 根仍优先。不向源码树写入安装布局，临时命名空间随会话销毁；对用户
所选源码的范围验证仍使用原始项目路径。该映射和实体 archive 的观察不进入持久化缓存。
每轮最多保留 256 个权威/物理卷映射。五种回调必须覆盖未保存文件及其虚拟父目录；缺失读取
返回显式空内容对象，不能触发原生后端的物理文件系统回退。目录只返回基名；非缺失 I/O、
无效 UTF-8、取消和快照预算错误均中止本轮。不同轮次不共享可变文件观察。
每轮至多 64 个配置项目、100,000 个项目内文件身份。项目配置使用原生 JSON/JSONC tsconfig
解析；配置错误及全局环境错误中止分析，普通源码的 TypeScript 语义诊断不直接充当 lint
诊断。所选源码必须属于一个实际 program；若属于多个 program，选择其所在目录最深的
配置，深度相同则要求消除歧义，不能任取第一项。不建立隐式空项目来接受被排除的文件。
查询绑定 program、快照与原文；配置、标准库和传递依赖观察与源码处于同一冻结文件系统。

读取帧、写入帧和应用协调分离，每个通道有界。帧头只接受大小写不敏感的单个
`Content-Length` 字段，拒绝未知或重复字段；单帧最多 32 MiB，头部最多 8 KiB，每轮传输
最多 256 MiB、200,000 个消息帧；超限、协议错误、版本不符或后端失败均为分析失败。
10 ms 间隔观察取消；会话有明确截止时间。取消、超时、失败及关闭均终止并回收自身子进程，
关闭管道并等待 I/O 线程退出；不能把挂起的子进程或后台线程留给下一轮。

后端 AST wire v5 只作为类型查询地址与范围的适配输入，原始语法与规则策略仍由 Wake 拥有。
适配器必须验证版本、偏移、节点/字符串边界及原始源码一致性，显式转换 UTF-16 与 UTF-8。
核心只接受 Wake owned、源绑定的有限类型事实及关系，不读文件、不启动进程、不访问后端
临时句柄。枚举声明/成员和 `unique symbol` 身份在适配器内映射为会话内的 Wake 身份，不能用后端句柄或成员拼写
替代；规则失败不得降级成名称猜测或把不完整类型图当作安全证明。
类型输入由核心解析其持有的原文后构建，调用、断言和模板的查询范围不能由应用另行拼装。
核心类型规则接收 Wake 编号的类型节点、联合/交叉成员、泛型约束、泛型实例实参、基类型、
匿名结构对象、接口、class 和映射类型的具名属性（名称、可选性、只读性和值类型，含索引签名值类型）、函数属性调用签名返回类型、
标准库符号身份及调用/构造签名；索引签名保留 Wake 编号的键/值类型和只读性，属性符号句柄不进入核心。
结构形状有显式完整性标志：未采集、调用/构造参数事实或属性写入权限不完整的对象不能按有限属性列表证明结构等价；完整空对象与缺失事实分别表示。
属性只读性由私有适配层对同一项目快照的声明 modifier 节点进行归一化；合成/映射属性不能仅凭原始声明推断写入权限，缺失证明时保持不完整。
已实例化映射和已验证的对象合成属性改用原生最终权限事实，先处理映射、const 和 spread 的覆盖，
再考虑源声明；数值标志仍封装在适配层，核心只消费具名只读集合。常量断言建立上下文，不参与
仅凭结果类型相等的冗余判断。
属性关系允许递归并由核心以单调固定点传播 any/error，不通过删除循环边来伪造无环图。
class/泛型实例的声明目标、类型实参与继承边分别保存，不能把未展开的
泛型实例误当成无继承关系的匿名对象；赋值与返回规则递归检查这些实参中的 any/error。有限字面量
identity 包括字符串、数字、布尔、bigint、null 和
undefined；bigint 以规范十进制文本传递，不能转换为浮点数。后端数字标志和句柄不进入核心。类型节点至多 50,000 个，关系和
签名至多 200,000 条；缺少调用事实、越界关系、无法完成的继承证明均中止分析。
字符串字面量使用 owned JsString，按 UTF-16 码元比较。7.0.2 的 JSON 字符串通道会替换
孤立代理项；含替换字符的值须用同一类型身份的 typeToString（NoTruncation）重新查询，
仅接受 Wake parser 验证的单个字符串字面量。类型别名/枚举成员名不是值恢复依据；不能
无损恢复的枚举值或结构属性名称中止分析。这些剩余恢复边界不计为 R6 已完成。
BigInt 事实只接受有效的带符号进制数字；空数字或非法数字字符必须终止本次分析并返回
`WAKE_LINT_ANALYSIS`，不能静默归一为零值。
`ts/no-floating-promises` 对原始表达式语句的最终表达式（含调用、动态 `import()`、裸标识符和
成员表达式）检查 Promise/PromiseLike 类型；表达式类型和标准库 Promise/PromiseLike 身份必须
来自同一批源快照查询。
`ts/no-misused-promises` 还接收调用参数、赋值、return 表达式、对象属性和 JSX 属性的实际函数签名与
原生 contextual 函数签名，用于证明 Promise/PromiseLike 返回的回调是否落入 `void` 返回参数；缺少 contextual type
或遇到 any、unknown、error 时 fail-closed。变量初始化和赋值位置复用同一份 assignment value
范围，return 位置复用 parser-owned return argument 范围，对象和 JSX 属性复用 parser-owned callback
value 范围，均接收实际与 contextual 函数签名；spread、any、unknown、error 或缺失事实不从声明文本
或目标名称猜测回调类型。
`ts/no-unsafe-call` 检查普通/可选调用、new 和标签模板的 any/error 类型，以及没有可用
签名的标准 Function 及其派生类型。联合要求每个成员具有该标准身份，交叉与基类型可由
一个成员证明；名称为 Function 的用户符号不能代替标准库身份。构造允许构造签名或非 void
调用签名，普通与标签调用允许调用或构造签名。动态 import 不接受虚构的 callee 类型。
诊断无自动修复；与局部规则共同执行后统一应用禁用注释、排序与基线。纯文本入口缺少
类型事实时必须失败，即使源码为空。规则默认关闭，既有版本化预设保持不变。
单源至多 16 MiB 原文和 100,000 个调用/实参、表达式语句、断言/操作数、模板/插值位置；语法错误保留
诊断并清空查询集合，不能把恢复树中的局部事实当成完整输入。
每个 wire 源文件至多 16 MiB 原文、500,000 个节点地址。原文必须与应用提供的 UTF-8 源码
逐字节一致，路径须匹配请求身份；类型节点以原生 parser 产生的原始范围绑定，不能接受只
匹配行号或名称的查询。UTF-16 中间代理单元不对应有效 UTF-8 范围，必须拒绝。
子表达式查询还须匹配已验证的父产生式与原始操作数或调用头范围；同文件中范围相似的其他
节点不能替代它。wire 的列表占位符只作结构连接，不作为类型查询目标；查找不能对每个
实参重复扫描整个文件或完整实参列表。

类型规则文件先绕过现有单文件持久缓存；后续持久化须另行记录 tsconfig、编译器、PnP/包
清单及全部类型依赖身份。watch/上下文沿用当前代次的观察发布与注册后重检。修复前后均需
使用匹配源码的类型事实，所有分析通过后才进入既有发布事务。

断言冗余判断只接受核心有限类型图的结构等价证明：字面量、联合/交叉成员、约束、继承边、
标准库身份、同一引用目标的逐项安全泛型实参以及接口/匿名对象的具名属性形状（名称、可选性、只读性和递归值类型）都属于比较输入；含 `any`、`unknown` 或 `error`
的不完整引用实参与缺失属性关系继续 fail-closed，仅共享基础类别不足以证明断言没有改变类型。
泛型引用目标按源绑定身份比较，实参按位置比较；索引签名的键/值及只读性参与结构比较。
递归等价证明的循环假设只存活于当前比较路径，失败尝试必须撤销；深度与工作量预算耗尽时不产生冗余断言诊断。

## Invariants

- 同一源码版本、配置和依赖产生相同类型诊断；不同项目的后端句柄不能混用。
- 不执行项目源码或 lint JavaScript 配置；类型服务只能提出受支持的只读文件系统查询。
- 缺失类型服务、未归属项目、协议/预算/取消失败均明确报告，不能返回伪成功的空结果。
- 前端、规则核心和 SDK 不依赖 TypeScript 临时句柄及其二进制布局。
- 子进程和 I/O 工作线程属于本轮会话；关闭后不得继续回调、输出或占用执行准入。

## Evidence

P0 本机实验验证了 TypeScript 7.0.2 多根项目、项目引用、PnP、未保存依赖与取消关闭。
直接原生协议实验验证 stdio JSON-RPC、五类只读文件系统回调、AST wire v5 节点地址、Unicode
位置和旧快照隔离。Rust 宿主与只读 PnP 投影已由真实原生进程验证，包括不同项目共享缓存
包、virtual ZIP peer、未声明依赖拒绝、取消及超时回收。编译器定位和源绑定事实已接入
`ts/no-unsafe-call`，通过 CLI、Node、最终修复、基线、上下文及声明文件监听测试。
帧读取回归还验证了未知或重复头字段、截断和超限输入均在结果发布前失败关闭。
当前只验收 Windows x64 实际原生进程；其他平台完成定位矩阵测试，实际运行与 tarball
仍属于 P7 门禁。十条类型规则均已接入同一源绑定事实适配器，泛型实参 any/error 递归事实
已由原生赋值/返回回归验证；同一泛型引用实参的断言等价及实参顺序已由核心回归验证。
同一项目跨文件 import/export 的关系事实、接口属性名/可选性/只读性、索引键/值/只读性与递归形状
已由原生 7.0.2 回归验证；完整 TypeScript 可赋值性和函数参数关系仍待 P5 扩展，不能把有限模型当作完整编译器类型检查。

## Consequences

类型服务复用真实 TypeScript 类型系统，规则策略保持原生；代价是显式的后端版本契约、进程
监督和协议适配。十条规则与未保存/PnP 项目路径已在 Windows 工作树验证；此候选尚未激活
机器边界，完整 P5 仍待验收。

## Validation

先验证有界帧与 I/O 生命周期的失败测试，再验证原生进程、回调、版本、取消/超时、后端退出。
随后验证原始范围、多项目、未保存依赖、PnP/zip、类型规则正反例、最终修复、CLI/Node/context/
watch、平台与 tarball。每个适配边界须验证无降级、无旧事实发布与无残留进程。

## Supersedes

None.

## Removal plan

没有旧类型宿主或持久化格式。协议升级必须增加版本矩阵和源绑定事实回归，旧适配仅在没有
公开兼容承诺且迁移已验证后移除。
