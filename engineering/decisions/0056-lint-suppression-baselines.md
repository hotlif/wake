# ADR 0056: 显式 lint 抑制基线

- Status: accepted
- Date: 2026-09-13

## Context

接入已有项目需要逐步偿还既有问题。行号随编辑漂移，自动接受模糊匹配会隐藏新问题；基线属于
用户审阅的输入，不能使用可丢弃的缓存写入语义。

## Decision

核心提供无 I/O 的基线指纹、唯一匹配与修复迭代抑制。应用拥有版本化 JSON 文档、规范相对路径、
生成/清理和结果统计；output owner 负责期望旧内容的原子替换及新文件的不覆盖创建。

文件 schema 为 `wake.lint.baseline.v1`，条目为 path/ruleId/messageId/fingerprint。指纹使用 SHA-256，
包含规则和消息身份、诊断覆盖的完整源码行（去除两端空白）及其中的诊断相对范围；不含绝对行号。
同文件同身份出现多次时全部保持可见，不使用序号或相似度。语法错误、无效/未使用注释指令不可基线化。

`--baseline FILE` 应用已有文件；`--generate-baseline FILE` 合并所选文件的当前唯一诊断；
`--prune-baseline FILE` 完整检查项目并删除已不匹配条目。三者互斥。生成和清理不接受 stdin、修复
或 max-warnings；清理不接受路径筛选。所有模式都返回 suppressed/stale/ambiguous/entries/written。
生成合并不删除旧条目；清理不添加条目，解析失败和被忽略的现存文件保留旧条目。

输入/输出必须为根目录内以 `.json` 结尾的普通路径，不跟随符号链接；父目录必须已存在。现有文件先验证完整
schema 才可能更新。至多 4 MiB、20,000 条；超限或结构错误在写入前失败。替换复核身份、内容和权限；
新文件以不覆盖提交防止覆盖并发创建。取消后不开始发布。

缓存保存注释抑制后的原始规则诊断，在命中后应用基线；内容键额外包含当前文件排序后的基线条目。
修复每轮都先应用唯一匹配，只有可见诊断进入编辑选择，返回最终源码的匹配统计。

## Invariants

- 基线不能抑制 parser 或指令错误；不以行号、计数预算或模糊上下文掩盖新诊断。
- 基线的路径与条目验证发生在源码发布之前；不把普通 JSON 或源码文件当成旧基线覆盖。
- 原始诊断缓存与最终抑制结果有明确顺序；基线变化不能复用旧有效键。
- 核心不读写基线；基线不通过缓存 owner 写入；跨文件源码和基线不承诺整体事务。

## Evidence

核心基线测试覆盖位置漂移、重复上下文、Unicode、指令和修复；应用与前端覆盖生成/检查/清理、
损坏输入、缓存失效及发布冲突。

## Consequences

上下文修改使旧条目过期，用户显式生成或清理。相同单行问题无法区分时均报告。基线不是永久忽略规则。
生成命令返回合并后可见诊断；未能基线化的诊断仍影响退出码。

## Validation

先运行目标失败测试，随后核心/应用/output/CLI/Node 契约测试、类型、Clippy、架构与文档门禁。

## Supersedes

None.

## Amends

- [ADR 0050](0050-native-single-file-lint-core.md): 核心可依赖纯哈希实现 ring，为源码上下文生成 SHA-256 身份；不增加 I/O 或运行时能力。
- [ADR 0055](0055-content-addressed-lint-cache.md): 补充基线条目身份与缓存命中后的抑制顺序。

## Removal plan

无旧基线格式；未知 schema 明确失败，不猜测迁移或覆盖输入。
