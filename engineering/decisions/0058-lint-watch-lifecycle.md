# ADR 0058: lint 文件监听与结果生命周期

- Status: accepted
- Date: 2026-09-13
- Amended by: [ADR 0063](0063-lint-module-graph-snapshots.md)

## Context

手动 LintContext 已有版本化文档和取消，但自动检查还需要文件事件、后台恢复与有界结果队列。
监听开始前的修改、目录替换和后端错误都可能造成漏检，不能把最后成功结果继续当成当前结果。

## Decision

应用层提供 RAII `LintWatcher`，持有 LintContext 并拥有 lint 专用文件监听、去抖和结果通道。
CLI 和 Node 共用此实现；不把 lint 加入 bundle/HTML 发布事务，也不改变 ADR 0037 的 build/dev 所有权。
监听固定规范根目录的源码与目录结构、根配置及已有基线；忽略生成缓存。根和最近现存父目录登记后才
开始首次完整检查。根/祖先结构变化或 backend error 使注册失效，重建后端并完整重新扫描。
每 250 ms 核对根与父目录的物理身份，发现目录替换或覆盖丢失也强制重建/扫描；不递归轮询源码，
不为正常项目监听无关的用户目录或整个磁盘根。

事件在回调中先使当前检查代次失效，再调度 50 ms 去抖检查。后端回调携带监听代次，退休回调
不能取消后继检查。后端不可用时报告执行诊断，以有界退避重试；注册恢复后必须再次完整检查。
文档更新和显式 invalidate 通过弱订阅通知同一调度器，不形成上下文/监听线程的所有权环。

每个 watcher 只有一个检查线程、一个待检查标志及最新开始/完成结果槽。快速事件合并，慢消费者
可以跳过中间快照；可见结果始终携带项目代次。错误结果也必须验证代次。停止只取消该 watcher
发出的检查并等待回收监听与线程，手动上下文仍可用；关闭上下文使所有监听停止。

CLI `wake lint --watch` 只接受只读项目检查选项，JSON 模式输出逐行事件，错误不结束监听。
Node LintContext 增加 startWatch/stopWatch 和 checked/diagnostic 事件；JS 主动读取结果，
不向已退出的 Worker 回调。显式 close 和环境清理都回收监听，重复开始/停止保持可预测。
监听启动使用 `LintContext::create_for_watch`：根和请求参数先验证，磁盘配置在注册后的检查中验证，
因此启动时损坏配置也能修复恢复。Node `createLintContext({ watch: true })` 采用此路径并自动开始。
普通手动 constructor 保持原有严格配置校验。

## Invariants

- 必须完成监听注册再作首次或恢复扫描；后端失效不能发布旧代次成功结果。
- 源码、配置、基线、创建、删除和重命名均能重新检查；损坏配置修复后可以恢复。
- watch 不写源码或基线；缓存目录事件不形成自触发循环。
- 后台持有 owned 输入/结果，队列有界；停止/关闭之后不再开始分析或发布事件。
- 停止监听不使手动上下文永久关闭，不取消后续手动请求。

## Evidence

应用监听测试覆盖首次扫描、真实文件/目录事件、配置恢复、基线变化、未保存文档、停止后手动检查。
确定性后端代次测试覆盖错误恢复及退休回调。CLI/Node 验证逐行输出、事件身份和退出清理。

## Consequences

首版每次事件重新发现项目，并通过内容缓存跳过纯单文件分析；未宣称完整依赖图增量。
支持平台的真实监听测试仍是发布门禁，单个 Windows 结果不能代替整个矩阵。

## Validation

文档/失败测试先行；应用监听和并发用例、CLI/Node 生命周期、现有 lint 回归、Clippy、类型与架构门禁。
