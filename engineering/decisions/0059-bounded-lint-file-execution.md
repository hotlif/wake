# ADR 0059: 有界 lint 文件并行执行

- Status: accepted
- Date: 2026-09-13
- Amended by: [ADR 0063](0063-lint-module-graph-snapshots.md)

## Context

项目入口按路径串行分析，多个 Node 请求分别占用协调线程。扩大文件数量时需要共享 CPU 容量，
又不能把所有源码和 parser arena 一次性送入无界队列，或并发修改基线与发布状态。

## Decision

应用层将独立单文件任务送入既有 wake_turbo 进程共享 executor；不为每个项目建立 CPU 池。
每个批次至多 min(32, workers) 个文件，全进程至多两个批次获得准入；等待准入期间可取消。
协调线程逐批读取源码，任务独占有效配置、源码、单文件缓存和基线数据；parser/semantic arena
在任务内创建和销毁，只返回 owned 诊断、修复文本及缓存/基线候选。

任务按输入路径归位；缓存候选与基线在协调方按此顺序合并，保留原有全批次尺寸/数量上界。
源码和基线写回仍由唯一 output owner 在检查完成后通过取消提交门禁执行。worker 不发布文件。
任务 panic 在 executor 边界转为 WAKE_INTERNAL，不得让共享 worker 死亡或让等待者永久挂起。
取消后已入队任务在执行前跳过，正在执行的单文件在返回后丢弃；本阶段不承诺 parser 内抢占。

## Invariants

- 不同线程数、批次划分和完成顺序产生相同诊断、修复、基线及缓存统计。
- 所有 lint 项目共用准入上界；关闭或取消能解除准入等待，不泄漏批次许可。
- 只读缓存命中仍校验诊断；同一配置/源码的缓存身份不因并发改变。
- 基线生成、缓存警告和首个错误按规范路径合并；任务失败不能提前发布源码或基线。
- 只有任务拥有解析器状态，公共上下文不保留 arena 或线程局部指针。

## Evidence

串行/四线程真实项目等价矩阵覆盖缓存冷热、基线、修复及未保存文档；受控任务验证同时执行、
进程准入上界、取消与 panic 后继续工作。

## Consequences

协调线程仍负责 I/O、配置、发现和发布；并行窗口按文件数量有界，单个大文件未设置新的长度限制。
Node 每个 one-shot 请求的协调线程和返回结果仍归请求所有，不能把 CPU 池上界解释为请求数量限制。

## Validation

先运行既有聚焦回归作为重构基线，再用并发失败测试验证目标缺口；应用、CLI、Node、Clippy、
类型、文档和架构门禁。

## Supersedes

None.

## Removal plan

删除主项目循环中逐文件直接执行分析的路径；stdin 也经过同一执行入口，无兼容执行器。
