# ADR 0089: 开发会话复用已验证的 Worker 产物

- Status: accepted
- Date: 2026-11-27

## Context

开发服务就绪前的第二次扫描必须读取当前输入。原生 Worker 子构建会释放编译状态，
大型 Worker 在两轮扫描中重复优化与生成，即使主图的编译任务全部命中。

## Decision

保留父构建会话最近一次成功构建所使用的顶层 Worker 产物。每个条目关联逻辑入口、
实际子构建选项、物理目标身份和该次子构建观察到的文件系统查询。每轮沿用资源所有权和物理边界检查，
在当前文件系统重新验证查询结果，包括内容、目录、路径身份和缺失结果。
匹配时向当轮引用模块发布入口、附属资源和原有诊断。失配时重新执行独立子构建。

## Invariants

- 一次性子构建顺序执行，退出时释放临时编译状态。嵌套 Worker 的输入属于外层 Worker 的观察范围。
- 七类文件系统查询分别按原始路径拼写记录。文件内容记录长度和 XXH3-128 指纹。同次构建内重复查询结果不一致时放弃保留该条目。
- 候选会话可以继承不可变产物。失败的候选不能影响已接受的会话。只保留当前引用的成功条目。
- 启动复扫和就绪条件遵循 ADR 0045。PnP 逻辑身份和物理资源边界遵循 ADR 0081。

## Evidence

`crates/wake_bundler/src/incremental.rs` 在父构建成功时保存产物，`worker_inputs.rs` 记录及复核输入。
同一 crate 的 `worker_artifact_` 测试覆盖候选复扫、嵌套依赖和 PnP 归档替换。

## Consequences

跨轮校验仍需读取输入，进程内保留产物和验证记录会占用内存。Worker 编译状态与持久化缓存格式沿用现有生命周期。

## Validation

验证无改动启动的两轮扫描合计只编译一次 Worker。比较输入变化、依赖解析变化及候选失败恢复后的产物与冷构建。
在真实应用中计量从启动命令到首页 HTTP 200 的时间，并检查复扫实际执行的子构建次数。

## Supersedes

None.

## Amends

- [ADR 0078](0078-native-worker-resource-urls.md): 保留独立顺序子构建和每轮输入观察，在输入验证通过时允许复用最近成功的 Worker 产物。

None.
